1 · Build and open locally

From skills/ax-skills/examples, with the collection dependencies and esbuild@0.25.12 installed:

npx --no-install esbuild browser/chrome-ai.ts --bundle --platform=browser --conditions=browser --format=esm --target=chrome138 '--external:node:*' --outfile=browser/dist/chrome-ai.js

Serve the examples directory using your local static HTTP server, then open http://localhost:PORT/browser/chrome-ai.html. Do not open it as a file: URL. For deployment, use HTTPS.

The SDK contains an optional Node worker import for its unrelated JavaScript executor. --external:node:* keeps that unreachable Node-only path out of browser resolution; the demo never creates an executor. Ax and its OpenTelemetry dependency are bundled locally, not loaded from a CDN. The generated browser/dist/ bundle is not source.

The entry uses minimal local DOM shapes. npm run check checks both the browser entry and the Node CLI; npm run build:browser creates the local bundle.

2 · Browser, hardware and first-download prerequisites

Use a supported desktop Chrome exposing LanguageModel in a secure context. Chrome 138+ extension support does not imply every ordinary web page or device supports the API. Web rollout, enablement and hardware/profile restrictions differ. Mobile Chrome is not a substitute.

Check the current Chrome Prompt API prerequisites and built-in AI setup guide. Chrome requires eligible desktop hardware and substantial free profile storage; its model is a separate initial download. Inspect chrome://on-device-internals for model state.

If Chrome reports downloadable, clicking a request button authorizes model creation and a potentially large download by Chrome. An unmetered connection may be required. This adapter does not expose download progress, so the page reports waiting honestly. Subsequent local inference does not need a cloud API key.

Unavailable is a valid result. Offline Node fixtures assert adapter protocol and cleanup only; neither those assertions nor loading this page verifies Gemini Nano, hardware compatibility, answer quality or successful model download.

3 · What the code teaches and where its boundary is
  • Answer constructs ai({ name: 'chrome-ai' }) and ax('question:string -> answer:string') from the click handler, then calls forward(..., { structuredOutputMode: 'native' }). Ax forwards a JSON Schema as Chrome’s native responseConstraint and parses the answer.
  • Stream calls the same provider’s real chat(..., { stream: true }). Every native successive text chunk is displayed separately, unchanged: no overlap removal, invented cumulative text or fake model response.
  • Each request owns a fresh session. Ax releases it on completion and prompt/stream failure. Cancel and page navigation abort the signal passed to creation and prompting; the demo also aborts on an interrupted consumer path. Partial text is not a completed answer.
  • This Ax adapter supports text conversations and native JSON Schema, not tools, media inference or embeddings. The underlying browser API may support more than this adapter.
  • Ordinary web pages omit numeric sampling. In Chrome extensions only, set temperature and topK together. When only one is supplied, Ax obtains the other from LanguageModel.params() (or legacy capabilities). Missing defaults reject before session creation; no guessed defaults are inserted.
