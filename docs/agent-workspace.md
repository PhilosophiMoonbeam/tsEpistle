# Wiki Agent workspace

Search and Wiki Agent have distinct entrances. Search finds pages as you type; the Agent helps interpret those pages and work with them. The header exposes both on desktop and mobile, with Ctrl/Command+K for search and Ctrl/Command+Shift+A for the Agent. Search results offer **Ask about this**, which prepares the current query and search scope as an editable request. **Open Wiki Agent** opens the workspace without sending a message. Unless a route-synced session is explicitly addressed, opening the inline workspace starts a fresh saved session; an explicit Search handoff may request a session resume, and a valid tab-scoped, account-matching pin may restore its session.

The Agent stays on the current Wiki route, preserving page context. Its single toolbar contains search, conversation identity, history, memory, conversation creation, and close. **New** creates a new saved session directly; **Temporary** starts a new temporary session. Temporary sessions have a highlighted action and an expiry notice with **Keep conversation**; Keep changes that same session to saved retention in place, preserving its ID and clearing its expiry. Temporary sessions stay out of Recent unless explicitly kept. Personal memory remains available in temporary conversations; temporary retention is not an incognito mode.

History and memory occupy independent columns at desktop widths. Between 1024px and 1759px, one panel can be open at a time; wider screens can show both. On smaller screens they use the existing modal focus scope and scrim. Container queries also adapt the toolbar and starters when a docked panel narrows the conversation. Closed panels reserve no space.

The visual language uses the application's local display typeface, warm accent, and light/dark surface tokens. The transcript and composer share a reading measure. Assistant text sits directly on the workspace; sources, activity, approvals, and goals retain their explicit disclosures. Page context sits above the composer. Keyboard focus outlines the entire composer so the inner textarea does not clip the indicator.

The composed request—text, goal mode, selected skills, source pages, and search scope—belongs to its conversation and stays in the in-memory workspace when switching between Search and Agent or closing and reopening the overlay. It is not written to browser storage and does not survive a page reload. Starting a new conversation opens a clean composer. A pin stores only its version, owner ID, and session ID reference in tab-scoped session storage (with an in-memory fallback when storage is unavailable); it does not change retention, memory, page/source context, draft text, or selected skills/scope. Same-tab navigation and reload can restore a valid owner-matched pin, while a new page context has no tab-scoped pin. Unpinning clears the reference, and the next open starts a fresh saved session. Pin chat is disabled while the workspace is loading or session selection, initialization, or mutation is unsettled; after the selected session commits and transitions settle it remains available during active responses and when provider inference is unavailable or disabled. The existing conversation is only replaced after creation succeeds; a failed request preserves its draft. Accepted submissions clear matching text, mode, and skills even if the composer has unmounted; reusable source context remains selected. Newer edits are preserved. If the same conversation reopens before submission completes, the store refreshes it in the current workspace to discover the accepted run.

Search results show available match fields (for example, title, tags, or page text) without presenting internal rank scores.

Welcome starters submit immediately when selected. Source and Search handoffs remain editable drafts until the user submits them. The empty workspace starts at the top after resizing; active conversations retain their existing follow-response behavior.
Mermaid diagrams render with their source disclosure closed by default. Rerendering preserves each user's open/closed source state (along with the existing focus, scroll, and copy feedback state).

## Token usage and provider completion

Agent usage preserves independently measured `inputTokens`, `outputTokens`, and provider-reported `totalTokens`. They are nonnegative safe integers, with `totalTokens` at least the safely added directional sum; the total is not derived by replacing it with that sum. Any remainder is intentionally unclassified, not reasoning, cache, tool, or another named category. Charged-token limits and settled reservation/daily/goal `consumedTokens` use the full total, while dispatch admission reserves a configured exposure bound once and never adds that hold to terminal measured usage; directional values remain truthful measured diagnostics.

Provider cost is conservative: the configured input and output rates apply to their measured directions, and the unclassified remainder uses the higher rate; the numerator and ceiling use `BigInt`. That residual pricing and any classification-based refund apply only to a validated provider-reported receipt. If usage is omitted and estimated fallback is explicitly permitted, accepted directions and totals are estimates—not measured usage—and cost remains the full admitted max-rate exposure without a residual refund. New usage-bearing events carry `usageVersion: 2` and `totalTokens`; the outer agent-event envelope remains `schemaVersion: 1`. Immutable legacy events are decoded only when both `usageVersion` and `totalTokens` are absent and the directional sum validates; that sum is exposed only as a lower bound, never as a reconstructed provider total. Invalid or mixed-era usage is rejected.

The current provider-path fix requires genuine SSE EOF before a response can complete usage reconciliation. A real one-fetch request to the configured external provider used a synthetic prompt and synthetic result content; profile/secret resolution and database inspection were read-only, with no maintained application, database, or provider state written. It returned HTTP 200 and reached genuine SSE EOF, but the old equality rejected its final text because `inputTokens=3`, `outputTokens=309`, and `totalTokens=4580` (unclassified remainder 4,268). The fix accepts a validated independent total at least as large as the directional sum and preserves it through accounting. This demonstrates the current deterministic equality defect and fix only. Conversation History and Agent Memory share a compact editorial header, readable accent colors, and consistent panel spacing. Desktop panels reserve 20rem for history and 22rem for memory while preserving the conversation alongside them. History titles wrap to two lines; folder creation sits with saved folders, and clearing Recent lives in the options menu. Retention copy follows the configured policy instead of asserting a fixed number of days.

Memory uses the full note width, puts record actions below the text, and filters across both memory stores without changing saved content or capacity. Empty results can be cleared directly. Editing focuses the input, blocks replacing an open edit, and keeps the panel open when Escape cancels that edit. Failed saves retain the draft. Clear-all remains behind an explicit confirmation in the options menu. Character limits, revision checks, stale-response handling, account privacy, and frozen conversation snapshots retain their existing behavior.

Folder deletion uses optimistic concurrency: the client sends the folder's current `expectedVersion`, and a concurrent change is rejected with `409` instead of deleting a newer folder. A successful deletion reports how many sessions were moved to Recent; failed deletion leaves the folder and its sessions unchanged for a refresh and retry.
Conversation folder names are canonicalized on the server with Unicode NFKC normalization, trimming, and whitespace collapse; owner-local uniqueness uses the lower-cased canonical name. Creation locks the owner row and performs the duplicate and count checks with the insert in one transaction, so the 32-folder cap is atomic under concurrent same-owner requests: one request can create folder 32, the other receives `409`, and another owner's create proceeds independently. Creating a folder for a conversation is still two transactions: create the folder, then move the conversation with its session-version check. A failure between them is a recoverable partial commit—the folder remains available for a move retry or reconciliation, and the conversation is not reported as moved until the second transaction is confirmed.
