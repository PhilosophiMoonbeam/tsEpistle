# Search foundation audit and execution record

## Status and evidence boundary

The retrieval foundation is implemented as a PostgreSQL-only, authorized lexical-plus-knowledge path. Canonical Wiki pages, immutable history, `pageTags`, page-access policy, and server-owned OKF authority remain authoritative. Revisioned knowledge projections are repairable derived state; personal memory remains a separate owner-scoped conversation snapshot. This work adds no embeddings, query-time provider expansion, source rewrite, second search service, or persistence solely for pagination.

The retained baseline, [`search-foundation-before-2026-09-07.json`](benchmarks/search-foundation-before-2026-09-07.json), is a PostgreSQL 17.10, seeded 20,000-page, 11-query lexical run. It measured recall@5 **0.8181818181818182**, MRR@5 **0.8181818181818182**, nDCG@5 **0.8181818181818182**, and zero-result rate **0.18181818181818182**. Its two diagnostic misses were `AFR` and `restore the ultraviolet verification code`; it is not a security, rollout, or model-quality pass.

The final isolated benchmark report, [`search-foundation-after-2026-09-07.json`](benchmarks/search-foundation-after-2026-09-07.json), is **passed** with no threshold violations. It records PostgreSQL 17.10 / `pg_trgm` 1.6, schema 2 with the English dictionary, 20,000 vectors, zero revision mismatches and orphans, a **25,772.876510 ms** rebuild, 30 samples per distribution after five warmups, and query p95 latencies of **26.583659 ms** for exact title/content (p50 23.742542 ms), **24.870621 ms** for typo/fuzzy (p50 24.150178 ms), **31.693809 ms** for multi-term description (p50 26.985204 ms), and **62.194827 ms** for common tag queries (p50 60.943106 ms), against the 200 ms query-p95 / 300,000 ms rebuild threshold. Its lexical acceptance scope is four required syntax/exclusion cases (quoted phrase, negation, `OR`, and empty input), all passed; the empty-input control intentionally contributes a zero result, so its aggregate MRR@5 is 0.75 and zero-result rate is 0.25, not a relevance regression.

The same report's **augmented fixture** scope is the original 11-query seeded corpus plus a current revisioned `pageKnowledgeProjections` fixture for page 42. It passed recall@5/MRR@5/nDCG@5 **1.0** and zero-result rate **0**, with no failed required cases. That is deterministic fixture evidence for the repository/union contract—title acronym `AFR` plus fixture-generated `concept.searchTerms`—and is expressly **not** live utility-model output or a universal semantic-recall claim.

## Before-state assessment and executed repair plan

The assessment found six load-bearing divergences. First, Agent-only projection union applied a separate bounded window after shared search, so it could evade shared publication-window/protection semantics and lose a selected knowledge-only page behind unrelated rows. Second, raw/private substring paths could diverge from quoted, `OR`, and negative structured syntax. Third, route-only hydration could attach a stale rank or projection to a replacement page. Fourth, blank private queries and caller-derived private limits could act unlike the documented empty/50-row contract. Fifth, lexical ordering of offset-bearing `verified.at` values could misclassify trust chronology. Sixth, projection link parsing could interpret code examples as links or fail on an overlong derived label. The audit also recorded incomplete revision absence behavior, publication empty-date/offset/invalid-window handling, a pre-authorization raw-500 cutoff, direct-draft authority matching, and nullable unknown link-line behavior as correctness/security boundaries.

Late native graph probing first exposed a confirmed security gap: a synthetic `publicSeed` 71 → `protectedBridge` 70 → `publicTail` 69 graph let `related(seed71, depth2)` return 70 and 69 through the protected bridge, while direct scoped-MCP `get(70)` was denied. The protected bridge’s body-only `Hidden relationship` entity also appeared in knowledge output, and graph search boosted public 71/69 from 6.75 to 7.4925 with `matchedFields: ["graph"]` from the protected edge. The protected-boundary repair was implemented and native-retested: related then returned `[]`, no protected knowledge remained, and both public scores dropped to 6.75; adding a public direct 71 → 69 link restored a distance-one related result and graph signal.

That retest had exposed a stale former 70 → 69 edge during a held running `links` receipt after canonical redaction/deprotection. The repair is now verified in [`search-graph-boundary-2026-09-07.json`](benchmarks/search-graph-boundary-2026-09-07.json): while page 70 revision 2's links receipt was running, `links[]` was empty and `related(depth: 1)` returned only public incoming 71, not stale 69. Releasing the held lease produced a succeeded links receipt and deleted old 70 edges. In session observation, deleting synthetic page 69's current render/links receipts let a normal worker recreate both as succeeded receipts at exact revision 1, demonstrating real bounded legacy render/link backfill rather than fake success; the retained artifact records this recovery via broad `legacyRenderAndLinksRecovered: true` alongside `receipts: []` rather than preserving individual receipt rows. Engine graph candidates now pin the authorized revision map before caps; source edges require a current succeeded `links` receipt; raw edge revision/routes are compared to the authorization snapshot. No model work or migration beyond 27 is involved. The invariant is now public, published, publication-window-open, unprotected, currently ACL-authorized graph nodes and edges only; protected endpoints are neither results nor bridges, do not contribute graph score, and knowledge attachment after related traversal needs a current body-read fence. Metadata lexical behavior remains separate.

The repair was executed in this order: (1) centralize one authorized union in `operations.search` and remove Agent-local fusion; (2) carry page ID/source revision through the engine and fail closed during hydration/exact-revision lookup; (3) make schema 2 / `wiki-knowledge-v2` a clean repairable cutover; (4) enforce structured syntax, pre-cap scope/ACL/publication/protection filtering, fixed private contribution, and correct time handling; (5) fence repair and utility work with immutable intent, source revision, and source hash; (6) update browser/API/MCP labels and exact-read/citation behavior; (7) retain distinct lexical, fixture, and actual-utility evidence. This is historical execution order, not an in-flight implementation plan.

## OpenWiki comparison and non-adoption boundary

OpenWiki is relevant for conservative provenance discipline, not as a component or product claim. Its Code Wiki Claims model uses stable claim IDs, resolver-owned versioned evidence, explicit stale/unresolved classification, and confirm/update/retract reconciliation. Its OKF projection preserves producer extensions and provenance, can retain line-precise evidence in sidecars, and advises preserving competing credible sources rather than resolving them merely by recency.

tsEpistle instead keeps authoritative Wiki pages/history, dynamic ACL, `pageTags`, and server-owned OKF authority in its database. It does not implement OpenWiki Claims sidecars, stable Claim/Evidence IDs, evidence reconciliation, or a contradiction model. Generated projection fields—including `relationships`, `openQuestions`, and `searchTerms`—are revisioned retrieval hints, not claims or evidence. Canonical OKF keeps the database taxonomy and authority boundary while preserving valid extensions/provenance; invalid/missing authority remains explicit. Neither projections nor OKF are auto-promoted into the owner-scoped personal-memory snapshot. If citable organizational memory is added later, it must be explicit revision-bound page/claim evidence rather than a promotion of generated hints.

## Implemented retrieval and authority contract

`operations.search` is the sole lexical-plus-knowledge fusion owner for browser, REST/GraphQL, Agent, and MCP. It receives locale, path, selected IDs, current ACL, publication, protection, and private-owner/system-manager context; obtains PostgreSQL lexical/graph and revision-matched knowledge candidates within those constraints; then applies one bounded deterministic ordering. The Agent-local knowledge union is removed.

Each candidate has canonical page ID and source revision. Hydration requires the same ID, revision, and route; a stale or mismatched candidate is discarded rather than relabeled by path. A projection attaches only when its source revision equals the hydrated page revision. A requested exact revision that is absent or mismatched fails closed—there is no fallback to current content. Expected locked/unavailable candidates are omitted without aborting unrelated results.

`matchedFields: ["knowledge"]` means **knowledge hints** only. It is not a verification state, factual authority, permission, page tag, canonical OKF metadata, or citation. Search, discovery, and related-page output are selection metadata; an Agent must read the exact current page or requested version before citing. The separate personal-memory snapshot remains owner-scoped and is neither populated from projections/OKF nor a substitute for Wiki retrieval.

Schema 2 / deterministic `wiki-knowledge-v2` is a clean stored-and-wire cutover. It requires bounded `searchTerms` (at most 20 terms, 120 characters each), persisted configured-dictionary `searchTokens`, and source revision. Schema-1 reads are unavailable; repair uses only validated immutable intents, with no compatibility alias or default shape. Deterministic acronym aliases persist; optional utility output may only fill a declared `concept.searchTerms` gap and is deduplicated without altering deterministic terms, source, `pageTags`, or authority.

Quotes, standalone case-insensitive `OR`, and token-boundary negation are structured syntax. Structured input receives no projection candidates and cannot fall through substring, fuzzy, acronym, or generated-hint paths. Ordinary hyphenated identifiers remain ordinary input. Trimmed-empty input returns no result on public, private, or knowledge paths. Locale/path (with literal `%` and `_`), selected IDs, ACL, current publication window, and protection filter candidates before their caps. The former raw 500-candidate cutoff no longer lets a pre-cap/unauthorized raw window hide an authorized result. Public candidates honor the full publication predicate: an empty date remains an allowed open bound where the page contract permits it; ISO timestamps with offsets compare as instants; an invalid date/window is not admitted. Protected body content and body-derived knowledge hints are excluded from direct lexical/knowledge matching; protected graph paths are resolved by endpoint/current-body fencing plus exact-current-revision succeeded-receipt gating. Private results remain requester-local; owner and system-manager path lookup use the same `canReadPage` authority, and their contribution is capped at 50 independently of the public limit.

Derived source handling is revision/source-hash fenced. Projection Markdown link extraction ignores code spans/fences, bounds labels, and keeps an unavailable source line as nullable/unknown rather than inventing a line number. OKF chronology compares valid `verified.at` offset timestamps as instants with a stable tie-break; undated-only evidence stays conservative. Missing or invalid authority is explicit and does not acquire trust from a projection. Direct draft reads require authority matching the editor context; they do not turn an editor-only draft into broadly readable source.

## Utility and concurrency boundary

Utility enrichment is an operator-approved **shared-content processor**, not a requester-scoped read. At preflight it checks current revision/source hash, public visibility, publication window, and password/protection state; it does **not** evaluate requester, page-rule, or anonymous-read ACL. It can therefore receive a published shared page that retrieval later withholds from a particular requester. A private, protected, unpublished, scheduled, expired, or invalid-window source found at preflight makes no provider request. Eligibility, revision, and source hash are checked again before output is retained. If they change after dispatch, the output is discarded and the job finalizes safely, but already transmitted bytes cannot be retracted. Retrieval continues to apply requester ACL independently.

The request has no tools, uses strict bounded schema output, fills only declared projection gaps, and cannot write page source, `pageTags`, authority, or verification state. It is not an injection-proof prompt boundary or a semantic-truth guarantee. Malformed output, timeout, unavailable provider, preflight ineligibility, or a race retains the deterministic projection.

Input and output are clamped to the resolved provider context/output capabilities. `maxActive` uses the configured `globalConcurrency` value to cap **knowledge leases across workers**; it is separate from Agent-run slot accounting and does not create one combined chat/background provider pool. New `searchTerms` backfill can invoke utility once for each eligible current page. There is **no shared per-user background-cost accounting, background per-user quota, or total backfill-cost quota**; before deployment, operators must approve the provider for that shared corpus and review corpus size and provider budget. Utility diagnostics retain model/profile/hash provenance but never source bytes, credentials, or raw request bodies.
