Opening a card never writes memory or submits an Agent message. Authored reference destinations and private documentation are not copied. ## Composed requests

A typed draft in the existing Pinia session coordinator owns text, message/goal mode, explicitly invoked skills, selected sources, search scope, and whether the current page is included. There is no browser-persistent draft storage. The current page is removable, and selected sources are distinct from skill attachments. Up to eight source pages can be attached. All Wiki, current page tree, selected pages, and a language scope carried from Search are supported. Welcome starters are the exception: selecting one submits it immediately; source and Search handoffs populate this draft and wait for explicit submission. Each workspace visit samples one of ten two-line greeting pairs, and the selected pair stays stable for that visit. The composer exposes **Skills** and **Goal** with their icons, while the header **Pin** action stores only `{ version, ownerId, sessionId }` and does not alter retention, context, or draft state. Its compact context controls cover search scope, **Add sources**, and the current-page summary. A disabled **Send** recedes in fill while its label and icon remain readable.

Submission snapshots the context. Validated source references and scope become part of run admission and its idempotency envelope, survive durable queuing, and propagate to research tasks and goal continuations. Search actions apply the selected scope at execution time. Page reads still enforce current permissions and revision checks independently. The transcript shows the scope and selected revisions used for each submitted question, even if the composer later changes.

Drafts remain memory-only. Reloading or closing the document uses the browser's unsaved-work confirmation while text, attachments, uploads, recordings, transcription, or a not-yet-accepted submission remains. Staying keeps the working draft; choosing to leave does not persist it in browser storage. Accepted input clears at the server-admission boundary, rather than waiting for the following thread refresh. Source or skill preferences alone do not trigger this warning.

Losing the connection keeps an already-open, still-authorized Agent and its draft visible. Server actions remain unavailable until connection and admission readiness recover; offline mode does not grant new work or preserve another account's workspace.

Early server-session creation remains intentional: the existing provider resolution and frozen memory snapshot are established when the conversation opens. Creating sessions lazily would change those semantics. **New** creates a saved session directly, **Temporary** creates a new temporary session with an hourglass action, and **Keep** converts the existing temporary session to saved retention without changing its ID. Agent and New controls use brief, intermittent theme-token border-beam highlights that fade between cycles and disappear when unavailable. Empty conversations are excluded from history, and replacement creation already preserves the previous draft on failure.

The conversation header identifies the resolved provider and Agent model. Its provider picker offers only authorized profiles and the workspace default. Changing provider preserves the unsent message and included Wiki sources, resets Web search consent, and does not submit a request. Active work, conversation mutations, uploads, recordings, and unsent attachments block provider changes with an explanation.

Opening History or Memory moves keyboard focus into its labelled panel. Closing, including Escape from that panel, restores its own visible trigger. Modal panels trap focus; docked and wide panels leave the rest of the workspace reachable. Owned menus/dialogs and composing input retain Escape ownership, and an in-progress memory mutation still fences dismissal.

The **You** and **Agent** crystals report character counts from the active conversation's frozen memory, not entry counts or newly saved memory. Their accessible descriptions and **Context details** distinguish the active snapshot and limits from latest saved memory that applies to the next conversation. Unknown, stale, failed and empty states remain distinct. Each crystal opens its corresponding section in the existing memory manager and closing returns focus to that crystal. On narrow screens, the context controls scroll independently so the message field and actions remain available; the numerical ring and labels remain usable with reduced motion and forced colors.

## Composer input and attachments

Desktop Enter submits, Shift+Enter inserts a newline, and Ctrl/Command+Enter submits. With a coarse primary pointer, Enter inserts a newline and the explicit Send control submits. Input-method composition does not accidentally send a message.

Up to four files can be attached. A multi-file selection is validated as a whole against the remaining capacity before uploading. Files upload sequentially to respect the server's single-upload memory admission gate and retain selection order. Failed filenames are reported without discarding successful uploads. Cancellation, conversation changes, and owner changes fence late results and clean up uploaded files that cannot remain attached. Paste and drop use the same admission rules; disabled or full controls explain why. Mixed text/file pastes preserve native text insertion, and that draft edit does not erase a file-rejection notice. The notice clears when admission conditions change.

Attachment input types follow the resolved Agent profile. Image creation and dictation use their separately authorized media profiles, so a profile that cannot consume audio attachments may still offer transcription. A full four-file selection disables both the visible Attach control and its native file input; removing a file restores admission.

Typing updates the in-memory draft synchronously without rewriting pinned-source preferences. Transcript clearance follows the measured composer height, and scroll updates are coalesced so a growing draft or streamed response does not repeatedly force layout.

The empty-conversation welcome grows into spare transcript space but does not flex-shrink below its intrinsic content height. In short viewports, its starter cards therefore contribute to transcript overflow and can scroll above the sticky composer dock instead of spilling behind it.

## Search workspace states and scope

Search names the current query and the effective corpus and filters. **Wiki** and **Saved offline** select the corpus; the separate **Filter from the current page** group displays the page's language and path before offering language and page-tree filters. Unfiltered online search is **All Wiki**. Selecting the already-active corpus does not clear filters. **Clear filters** keeps the query and corpus, broadens the search, and returns focus to the input; it is available in the filter group and scoped no-results recovery. Offline filter controls remain focusable with a visible explanation, but unapplied filters are never shown as active.

Initial loading uses a full loading state. Query and scope refreshes retain previous rows and suggestions with their original query/scope context and unavailable actions. A failed refresh leaves those rows readable, clearly marks the failure, and offers retry rather than presenting the error as an empty collection. Fresh zero-results states show a truthful zero count, recovery choices, and one Agent draft action, not competing duplicate Agent buttons.

Online summaries distinguish returned rows, total matches, and bounded-window lower counts. Saved-offline summaries report matching saved pages; the separate hint reports how many saved pages were searched. Truncated downloaded results use a `+` lower-bound match count, not the size of the downloaded corpus as a match count.

Continuation cancels on a new query, retry, mode change, offline-session change, close, or unmount. Late responses and late cleanup cannot overwrite or stop a newer continuation. Appending pages preserves keyed rows, scroll context, selected result identity, and suggestion position. Errors retain loaded pages and offer **Search again** for expired continuation recovery. When the final continuation removes its focused button, focus moves to the newly added result or the input.

The Add Sources dialog transfers focus from a disappearing, keyboard-focused continuation button to the first enabled newly added checkbox, or back to its query input when nothing usable was added. The hidden native checkbox receives focus without native ancestor scrolling; only the results list scrolls to reveal its row, preserving the modal's visible contents. Cancellation, a replacement query/dialog, or an intervening user focus move prevents that transfer.

Cancel discards pending source additions without changing the current draft. Cancel and Apply return focus to the actual header or composer ring when it opened the picker; ordinary **Add sources** cancellation returns to that button, and its successful Apply returns to the composer.

Result titles wrap without truncation; descriptions remain bounded and paths wrap. Preview has a separate target rather than overlapping the result link. Below 600px, Preview moves beneath its row with a visible label and full touch target. The mobile header field is 44px tall with 16px text in a 52px extension; the Search overlay starts below that extension.

The Search panel is one continuous vertical scroller containing corpus controls, page filters, query context, results, Preview, continuation, and keyboard hints. Its content cannot flex down to zero height beneath fixed controls. Enlarged text and short or narrow viewports scroll the entire workspace instead of clipping results behind the scope area; controls remain in natural DOM/focus order, and keyboard-selected results scroll into view within the same panel.

Desktop corpus choices and the available page filters share a 40px-base toolbar. Narrow layouts and enlarged text keep controls in an intentional horizontal scroller; keyboard focus reveals the active control rather than leaving it clipped outside the viewport. Matching passages render as escaped text with amber marks and at most two visible lines, beginning near the first actual match. A metadata-only hit does not invent a body passage. Ask's hover/focus explanation remains draft-only; changing corpus or filters never sends a prompt.

Saved-offline rows omit the entire Preview cell and its unavailable-preview explanation. Their actual storage, locked-vault, capability and reconnect notices remain. Private cached reading uses normal vault setup, secret re-entry and unlock, followed by a current authorized snapshot save. Document navigation retires the in-memory key; unlock again in the saved-pages library before private Search can expose a row. The local row opens the admitted snapshot's exact page identity, source revision and rendered body, including while the browser is offline, without repairing it from the live wiki.

Private-vault verification must suppress automatic snapshots, screenshots, trace/video/HAR, API-value/protocol logging and session recording before the one-time secret appears and hold that boundary through cleanup. Inspect effective tool settings and the selected command's implementation; raw output mode alone is not capture suppression. Never record the generated secret or import authentication/keyring state. Restore the prior Search query, corpus, available filters and focus through normal controls, then retire only the owned disposable profile and fixture data.

## Search coverage and continuation

PostgreSQL search accepts authorized page identities before lexical, exact, fuzzy, and graph ranking caps. Current metadata and page rules produce those identities; protected pages qualify only through searchable metadata. Selected-page scope constrains both public and private candidate queries. Search results are rehydrated from current metadata before returning them. Exact page paths bypass unnecessary broader lexical/fuzzy matching.

Online content matches include a bounded passage from the currently authorized source revision. Metadata-only matches return no body excerpt; they do not invent a passage or expose protected content. Saved-offline search derives passages only from the current audience's authorized downloaded snapshots. Matching excerpts do not change ranking, result counts, cursors, or continuation bounds.

The browser requests 20-row pages from a bounded result window. Continuation keeps a five-minute snapshot of ordered identities, tied to the user session and query. It caches no page contents or excerpts. Each continuation reruns permission-aware retrieval restricted to the original numeric page IDs before ranking caps, then fills the next page from still-visible snapshot identities, preserving order across ranking changes and removals. New higher-ranked pages cannot displace the original tail. Snapshots are bounded to 128 process-local entries and expire across restarts; multiple replicas need instance affinity for continuation. An expired cursor asks the user to search again. Counts are explicitly lower bounds when the retrieval window is capped; scope and query refinement remain available.

Malformed explicitly supplied locale, path, cursor, or pagination values—including duplicate/array/object query forms—return HTTP 400. A well-shaped but invalid or expired continuation returns HTTP 409; neither case silently becomes a fresh search.

The permission prefilter currently reads scoped public metadata to evaluate the application's existing page-rule logic. This prioritizes one consistent authorization policy over a second SQL implementation. Large deployments should monitor whole-request latency and metadata volume; the included engine benchmark does not claim to measure that entire HTTP path. PostgreSQL is the sole maintained provider, and registry refresh rejects missing or unusable definitions before changing saved configuration.

Markdown page-link completion preserves public/private route identity and encoded path segments. Private destinations always retain their mandatory locale segment; public destinations follow the site's language namespacing. It consumes each matching cursor's own pre-existing closing parenthesis independently, including mixed autoclosing and pasted unfinished links, without skipping secondary cursors.

## Answers and changes

Completed answers offer **Copy answer with source links** and **Save as Wiki draft**. Saving opens an editable Markdown review with title, locale, path, and rendered preview; opening, preparing another draft, and closing do not write a page. **Copy reviewed Markdown** exports the edited review separately from the unchanged canonical answer export. The explicit **Create private draft** action creates a new private, unpublished page through the existing page API. It never overwrites an existing page, and creation errors preserve the reviewed content.

The review checks authorized earlier creations for that exact answer when opened. **Created while reviewing this answer** identifies origin, not an immutable match to the answer or a synchronized copy. Receipts distinguish the committed creation revision from the destination's current revision, current audience and publication state. **Open draft** uses only the currently authorized destination; a committed but unavailable destination exposes no old title, path or link. **Load more drafts** continues the receipt list, and **Refresh earlier drafts** performs another read-only check.

A creation attempt captures one request identity. If its response is lost or cannot be confirmed, the review blocks another submission and offers **Check creation status**, a read-only lookup that cannot create a duplicate. Unknown, missing, or inaccessible results never mean the attempt was rejected. A definite rejection allows a deliberately corrected new attempt; a confirmed commit offers **Prepare another private draft**, with a new destination suggestion and a new request identity on explicit creation. Multiple intentional drafts are allowed. Identity, permission, or answer-context changes cancel receipt reads and remove destination metadata; recoverable Markdown stays in memory for its owning account and answer, not in browser-persistent storage or another account's display. Reloading the document does not preserve unsaved review text.

Existing Agent edit proposals retain their immutable diff, revision checks, and approval controls. Mermaid source disclosures are closed by default and preserve each user's open/closed state when rendered output is refreshed.

Terminal assistant messages carry a bounded, owner-scoped `runOutcome` with terminal status and an optional error code; it does not keep a finished run in `currentRun` or expose provider error messages. Partial, failed, and cancelled answers retain truthful recovery states after reload. Review request restores an editable draft and never resubmits it automatically.

Governed changes report their recorded outcome rather than treating a mutation as an unanswered source question. Applied receipts identify the exact proposal and committed result; denied decisions identify the proposal that was not applied. These receipts establish operation status, not page-content facts. An unrelated missing fact can still make the answer partial without concealing a completed change. Missing or no-longer-readable page metadata is not proof that the page was deleted.

Transcript proposal diffs keep horizontal code scrolling local, but vertical wheel input can continue into the transcript at the diff's edge. Reading earlier messages must not trap the pointer inside a short diff or make the approval-navigation control unreachable.

Activity labels name the action and its status. Running or exceptional activity opens by default, while a user's native disclosure choice survives transcript updates. Completed message entrances are static; animation and decorative live indicators are confined to live work. Presentation caches retain unchanged entry identities and invalidate when content, locale, time, or origin changes.

## Token accounting and provider completion

Agent runs retain independently measured `inputTokens`, `outputTokens`, and provider-reported `totalTokens`. The total is a nonnegative safe integer at least the safely added directional values and is never derived from them; `totalTokens - (inputTokens + outputTokens)` remains an intentionally unclassified residual. It must not be presented as reasoning, cache, tool, or another invented category. Charged-token limits and settled reservation/daily/goal `consumedTokens` use the full total, while dispatch admission reserves a configured exposure bound once and never adds that hold to terminal measured usage; direction fields remain measured diagnostics.

Conservative cost applies the configured input and output rates to those directions and the higher rate to the unclassified residual, using a `BigInt` numerator and ceiling. That residual pricing and any classification-based refund apply only to a validated provider-reported receipt. If usage is omitted and estimated fallback is explicitly permitted, accepted directions and totals are estimates—not measured usage—and cost remains the full admitted max-rate exposure without a residual refund. New usage-bearing events use `usageVersion: 2` plus `totalTokens`; the outer agent-event envelope remains `schemaVersion: 1`. Immutable legacy events are accepted only when both fields are absent and their directional sum validates, yielding a lower bound rather than a reconstructed total. Invalid, mixed-era, and unknown-version payloads are rejected. Admission reserves whole-token exposure before dispatch; a valid complete receipt settles once with its full total/cost, releases only its original hold from reserved counters, and charges the full actual to consumed counters. Positive pending settlement blocks reclaim/expiry/cancellation release/top-up, and unavailable settlement remains conservative rather than reporting success.


## Evaluation

The dedicated PostgreSQL benchmark now includes relevance at five results, reciprocal rank, nDCG, zero-result rate, and per-case latency across exact titles, content terms, typos, paths, descriptions, related concepts, abbreviations, paraphrases, locale/section scope, and selected identities beyond the ordinary result cap. Scope violations fail the evaluator. Run it only against a dedicated database ending in `_postgres_search_benchmark`; it recreates that database's benchmark schema.

The committed [2026-09-06 report](benchmarks/search-agent-2026-09-06.json) used 20,000 generated pages in an isolated PostgreSQL benchmark container. It records two lexical relevance gaps—abbreviations and paraphrases—rather than treating absent results as success. This is the comparison baseline for a future configured semantic retriever; no additional embedding provider or index is required by this change.

## Validation and rollout

Token-accounting rollout is a coordinated **drain workers → migrate → deploy all nodes → restart** cutover with no mixed old/new writers. Drain and stop every agent-state writer before applying `tsepistle-000031-agent-total-token-accounting.ts`; its `agentRuns.totalTokens` backfill stores only validated directional sums as lower bounds and never rewrites quota-ledger history. Deploy the current writer to every node before restarting or restoring admission; see [Agent deployment and operations](agents-deployment.md) for the operator sequence.

**Validation scope.** Provider and workspace changes use focused component/store/API/host checks, applicable typechecks, lint, production builds, and bundle-budget checks. Ordinary media fixtures use SQLite; full-suite, native PostgreSQL, and large-PDF coverage are separate checks. Live provider execution and deployed browser flows supply behavioral evidence that unit checks alone cannot provide.
