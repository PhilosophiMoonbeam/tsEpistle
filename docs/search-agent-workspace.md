# Search and Agent research workspace

Search locates knowledge; Wiki Agent works with it. Desktop and tablet headers keep direct Agent and icon-only **Browse by Tags** entrances. Below 600px, those actions remain available in the existing **Page actions** menu; Search and Account stay direct, with full-sized touch targets and room for the workspace title. Closing an Agent opened from that menu restores focus to the stable menu activator rather than its hidden row. The rounded **Pin** control sits in the Agent header beside **New**. **Ask about this** prepares an editable question and carries the current search scope into the Agent. Source and Search handoffs remain drafts; they never start a model request by themselves. Existing unsent text is retained when preparing a handoff. When no route-synced session is explicitly addressed, the Agent workspace opens a fresh saved session unless this handoff requests a resume or a valid tab-scoped, account-matching pin restores one. **Pin** remains disabled while the workspace is loading or session selection, initialization, or mutation is unsettled; after the selected session commits and transitions settle, provider inference being unavailable or disabled does not by itself disable the pin.

On desktop, **Browse by Tags** sits immediately before Search with the same 8px gap as the other grouped header buttons. The command group is bounded to Search's maximum width so wider headers do not separate the two controls; Search remains centered.

The configured workspace title is one continuous, direction-aware header label: long names use single-line ellipsis with the complete title available on hover, rather than inserted spaces or resize-dependent word splitting. Account avatars remain 32px; healthy connectivity uses an 8px indicator without shrinking the Account touch target. Offline or failed connectivity retains its stronger status treatment and an explanation in Account, where unavailable server actions remain guarded.

Reader Search offers **Wiki**, **Saved offline**, and **Glossary**, in that order. Wiki is the default; Glossary no longer consumes a header button or a Page actions entry. The same header field filters terms, aliases, expansions and categories. Glossary adds its own catalog locale, A–Z/initial and category controls, a paged directory, and in-place definitions with related terms, documentation and references. It uses the existing Search surface rather than nesting another modal or glass layer.

Page term links and `?glossary=` URLs open that same Glossary search type. Selecting terms, browser Back/Forward, locale changes and closing continue through the reader's navigation controller. Modified term-link clicks retain native new-tab behavior. The header field is a searchbox in Glossary, not a page-result combobox; Tab reaches filters and term links, and Enter activates a focused term. Page-tree filters and page-result keyboard actions are absent from this type.

Management controls remain permission-gated. Unsaved Glossary edits and active saves guard switching search type, closing Search, opening Agent, page navigation and document unload. Typing in the shared header does not discard an edit; its query applies when the user returns to Directory. A server outage or offline state is shown inside Glossary without presenting its results as Saved offline, and terms are not persisted as an offline catalog.

Authorized article terms also offer 280px definition cards on hover or keyboard focus; the first touch opens the aid without navigating, and a second touch dismisses it. The card uses the article's locale independently of the directory locale picker. Tab reaches its controls, Escape restores owned focus, and **Open full glossary** opens the same selected definition in Search. Tall definitions scroll within the available space above or below their trigger rather than covering and reactivating it on dismissal. Open cards revalidate access; offline, disabled and revoked states remove resident definitions instead of reusing an authorized-looking stale result.

**Pin to my memory** deliberately saves the visible term, locale, expansion and definition, with canonical source/glossary context, to the current user's private memory. Opening a card never writes memory or submits an Agent message. Authored reference destinations and private documentation are not copied. Identical content reuses the existing record, including when capacity is full; over-limit or unsafe content is rejected rather than abbreviated, and a failed save never shows success. The memory manager shows the saved record after reload. Existing conversations retain their frozen memory; the saved value applies to new conversations.

Cards are article-only, including Focus; Talk, Links and the actual Print composition retire decoration. Page, locale, connectivity and account changes fence pending definition and Pin responses: a server-committed memory remains saved for its original owner, but its receipt cannot mark another selection saved. Reconnecting restores Pin only when normal transport and authentication checks pass; nothing is queued or automatically resubmitted.

Opening Agent from an already-open Search dialog retires the previous Search focus scope before capturing the rendered menu activator. Vuetify's activator slot retains its own ref; restoration targets the actual overflow button.

Shared outlined form fields use Vuetify's native notched focus boundary. The notch owns the 6px clearance on either side of its label; adding padding to the intrinsically sized floating label can clip even short text such as **Email Address**. Solo Search keeps its continuous native boundary. Both variants retain keyboard focus visibility, including forced colors, without a second wrapper outline.

Nothing is sent.** Full-page **Focus** is a labeled hero action; **Edit** remains separate and permission-gated. The preview's own focus scope restores focus and leaves the search query, result position, and conversation in place. Unavailable and locked sources have explicit states.

The source reader retains its header and actions around a separately scrolling excerpt when height permits. Below `38rem` of available overlay height, it becomes one continuous panel scroller with header, excerpt, and actions in flow. This root-relative height threshold also accommodates enlarged text and short landscape viewports without hiding actions or reducing the user's text size.

Nonmatching or nested headings, authored navigation links, and legitimate inline artwork remain visible. The full-page hero contains factual update/author metadata, labelled **Focus**, **Save offline** and **Share** actions, and one permission-gated **Edit** shortcut. Stored shortcut preferences resolve to that single article action, not a floating Edit button or a second menu Edit. Watch/settings, approval/protection, Print, View source and History remain current-page- and permission-aware. Full width is omitted below the useful 1145px width. Default automatic contents placement uses a 224px right rail at 1280px and wider and one collapsed sticky **On this page** control below that breakpoint. Fresh reading width is 76ch, while valid saved typography remains intact. The same searchable, non-marquee outline retains its filter, branches, current section and focus across rail, compact disclosure and Focus picker.

The saved reading measure bounds the complete authored article, including notices, disclosures, tables and code, rather than centering only selected prose elements inside a wider canvas. **Full width** remains the explicit opt-out. Inline contents uses compact sizing at every viewport width, including desktop with a saved Left placement; a collapsed disclosure does not reserve an empty rail-height panel.

Touch hero controls retain a 44px minimum height. Share keeps its accessible name while open; Enter, Space, and arrow keys enter its enabled actions, and Escape restores its trigger without activating a sharing destination. Responsive navigation follows the actual CSS breakpoint, including mobile visual-viewport settling, rather than retaining a temporary zoom-derived width.

Online Share's native and public-provider actions require the site's explicit `publicSocialSharing` opt-in, a valid HTTP(S) destination, verified online transport, current publication, and the server's explicit `publicSharingEligible` proof. That proof uses the canonical Guest principal's current locale/path/tag read authority and excludes protected pages; public visibility, writer access or a password unlock alone is insufficient. SSR and SPA navigation carry the same proof, with an absent value failing closed. Pending navigation, retired reader authority and non-article views cannot reuse it.

Copy link, Markdown link, current-section link, page text and email remain separate actions with their existing destination/content guards; they do not grant recipients access. The saved-page library has a distinct local-copy/share contract, described in [Offline platform behavior](pwa-offline.md#9-install-update-sharing-and-platform-behavior), not a public-provider eligibility exception.

One Sources group owns the attached Wiki-page chips. Each chip has sibling Preview and Remove buttons, never nested interactive controls. Add sources searches across All Wiki; the separate scope control limits the Agent's next Wiki search. Selected-pages scope is unavailable until at least one source is attached.

The Sources meter counts committed Wiki attachments only, up to eight. Pending picker additions, search scope, retrieved evidence, tokens and answer quality do not contribute. The current page is a separate inclusion hint, deduplicated against attachments and not charged against those eight slots; do not present it as a second source chip or a misleading nine-slot capacity. Source access is rechecked before use.

Search has an explicit **Close search** control that exits the workspace and restores focus to its opener. **Tab** and **Shift+Tab** use the existing modal focus scope: the header input, corpus choices, page filters, native result links, Preview, continuation, and Close remain reachable without clearing the query. Escape leaves Search; composing text does not trigger search shortcuts. With focus in the visible header search input, **Alt+Enter** previews the keyboard-selected result only when it is a fresh online wiki result and the server is verified live; downloaded-page results, suggestions, and loading or stale results do not offer that preview. This shortcut neither navigates nor submits an Agent request. The existing **Ctrl/Command+Enter** shortcut explicitly enters Agent and submits through its established handoff; **Ask about this** and source actions remain draft-only. Closing a preview or pressing Escape returns focus to the search input while retaining the query and result cursor. Modified clicks on fresh results retain native link behavior and leave search in place. Stale rows cannot navigate, including through modified or middle clicks.

The shared modal focus scope also preserves native traversal into embedded documents such as the Draw.io editor. When a keyboard boundary wraps into an iframe, it focuses the iframe after the cancelled key event finishes; it neither reads the foreign document nor chooses its internal focus target. A browser may first focus the frame document before its controls. Closing the scope or moving focus elsewhere cancels that pending handoff, and background isolation and opener restoration remain unchanged.

Direct Tab entry into desktop Search keeps focus in that input when dismissed, so the next Tab continues forward through the header actions. Shortcut and mobile openings restore their actual opener. The active Search/Agent modal owns Escape; header controls must not perform a second focus restoration.

When the desktop/mobile breakpoint replaces the currently focused Search input, focus moves to its visible replacement without clearing the query. Breakpoint changes do not move focus out of an open source preview.
Automatic reopening of permanent desktop navigation does not move focus into the drawer; temporary mobile navigation retains its opening focus behavior.

The offline shell bundles the same search and page-selector control labels, including filter match counts and empty states, without fetching a locale catalog. Destructive library actions retain their full explanation of which unlocked vault and site are affected.

The full page reader leaves disclosures under native, individual control: click or keyboard-activate each summary to expand or collapse its content. There are no bulk disclosure actions or expanded-count strip, and authored open states and named exclusive groups retain browser behavior. Browse lists the current directory's folders and pages without a directory filter, match count, or duplicate current-directory heading; the ancestor trail remains available for navigation.

Reader-owned action wrappers and controls introduce neither clipboard text nor extra paragraph breaks. Copy does not toggle a disclosure or intercept native selected-text copy. Search rows without a current rendered passage keep Copy unavailable rather than copying an assumed body.

In **On this page**, hovered and current-section labels use on-surface ink so saved custom palettes retain readable contrast over the active tint and glow. The solid inline-start edge continues along the bottom, follows the row's existing rounded corners, and fades toward the opposite edge, without changing section navigation or scroll tracking.

Initial rendering and in-app navigation use the same reading fingerprint: formatting-only HTML whitespace and empty framework fragment markers do not reset coverage, while whitespace inside preformatted blocks remains significant. ## Composed requests

A typed draft in the existing Pinia session coordinator owns text, message/goal mode, explicitly invoked skills, selected sources, search scope, and whether the current page is included. There is no browser-persistent draft storage. The current page is removable, and selected sources are distinct from skill attachments. Up to eight source pages can be attached. All Wiki, current page tree, selected pages, and a language scope carried from Search are supported. Welcome starters are the exception: selecting one submits it immediately; source and Search handoffs populate this draft and wait for explicit submission. Each workspace visit samples one of ten two-line greeting pairs, and the selected pair stays stable for that visit. The composer exposes **Skills** and **Goal** with their icons, while the header **Pin** action stores only `{ version, ownerId, sessionId }` and does not alter retention, context, or draft state. Its compact context controls cover search scope, **Add sources**, and the current-page summary. A disabled **Send** recedes in fill while its label and icon remain readable.

Submission snapshots the context. Validated source references and scope become part of run admission and its idempotency envelope, survive durable queuing, and propagate to research tasks and goal continuations. Search actions apply the selected scope at execution time. Page reads still enforce current permissions and revision checks independently. The transcript shows the scope and selected revisions used for each submitted question, even if the composer later changes.

A sent welcome starter displays a compact intent label while retaining the complete submitted request in an accessible disclosure. Only its explicit validated `presetId` supplies that label; custom and legacy messages are not classified from familiar wording. The durable request and user-message metadata contract is documented in [Agent operations](agents-deployment.md#current-normative-runtime-and-recovery-contract).


Drafts remain memory-only. Reloading or closing the document uses the browser's unsaved-work confirmation while text, attachments, uploads, recordings, transcription, or a not-yet-accepted submission remains. Staying keeps the working draft; choosing to leave does not persist it in browser storage. Accepted input clears at the server-admission boundary, rather than waiting for the following thread refresh. Source or skill preferences alone do not trigger this warning.

Losing the connection keeps an already-open, still-authorized Agent and its draft visible. Server actions remain unavailable until connection and admission readiness recover; offline mode does not grant new work or preserve another account's workspace.

Early server-session creation remains intentional: the existing provider resolution and frozen memory snapshot are established when the conversation opens. Creating sessions lazily would change those semantics. **New** creates a saved session directly, **Temporary** creates a new temporary session with an hourglass action, and **Keep** converts the existing temporary session to saved retention without changing its ID. Agent and New controls use brief, intermittent theme-token border-beam highlights that fade between cycles and disappear when unavailable. Empty conversations are excluded from history, and replacement creation already preserves the previous draft on failure.

The conversation header exposes one **Capabilities** surface with the actual enabled/blocked reasons, not a provider/model picker or raw profile identity. Model resolution remains administrator-controlled. Inspecting capabilities, source context or history does not submit the draft.

Opening History or Memory moves keyboard focus into its labelled panel. Closing, including Escape from that panel, restores its own visible trigger. Modal panels trap focus; docked and wide panels leave the rest of the workspace reachable. Owned menus/dialogs and composing input retain Escape ownership, and an in-progress memory mutation still fences dismissal.
**More chat actions** accepts ArrowDown into its first visible enabled action and ArrowUp into its last. Escape closes the menu and returns to that exact trigger; compact Memory opens from the same menu without leaving its active modal panel inert.


Opening or resuming historical work starts at its first substantive assistant response with follow-latest disarmed. Manual reading remains in place while content arrives. Only explicit **Send** or **Latest** may re-arm following; focusing or typing in the composer, reaching the bottom, hover and near-bottom heuristics do not. **Latest** remains readable over the transcript backing.
Accepted submissions keep following through normal stream-readiness and terminal-refresh transitions. Account, workspace and session transitions still cancel pending transcript measurements; connection readiness alone does not retire the current conversation's reading position.


The **You** and **Agent** memory meters report actual character usage from the active conversation's frozen snapshot against the 1375/2200-character limits, not quality percentages or newly saved memory. Accessible descriptions distinguish that snapshot from latest saved memory used by the next conversation; unknown, stale, failed and empty states remain distinct. Raw versions and hashes live behind explicit copy controls. **Context details** is one bounded native disclosure, with scroll controls only when its open body genuinely overflows; the summary keeps native keyboard behavior. Compact layouts retain readable context controls without burying the message field, including reduced-motion and forced-colors modes.
Its complete box, including padding and border, is capped at the smaller of 24rem and 40dvh; overflowing details remain scrollable without enlarging the workspace.

## Composer input and attachments

Desktop Enter submits, Shift+Enter inserts a newline, and Ctrl/Command+Enter submits. With a coarse primary pointer, Enter inserts a newline and the explicit Send control submits. Input-method composition does not accidentally send a message.

Up to four files can be attached. A multi-file selection is validated as a whole against the remaining capacity before uploading. Files upload sequentially to respect the server's single-upload memory admission gate and retain selection order. Failed filenames are reported without discarding successful uploads. Cancellation, conversation changes, and owner changes fence late results and clean up uploaded files that cannot remain attached. Paste and drop use the same admission rules; disabled or full controls explain why. Mixed text/file pastes preserve native text insertion, and that draft edit does not erase a file-rejection notice. The notice clears when admission conditions change.

Attachment input types follow the resolved Agent profile. Image creation and dictation use their separately authorized media profiles, so a profile that cannot consume audio attachments may still offer transcription. A full four-file selection disables both the visible Attach control and its native file input; removing a file restores admission.

Typing updates the in-memory draft synchronously without rewriting pinned-source preferences. The opaque composer is a normal in-flow footer outside the transcript scroller, never an absolute scrim over answer text. Its empty target is at most 132px; measured content and safe-area clearance still accommodate real attachments or a growing draft. Scroll updates remain coalesced without forcing follow-latest during manual reading.

The empty-conversation welcome grows into spare transcript space but does not flex-shrink below its intrinsic content height. In short viewports, starter cards contribute to transcript overflow above the in-flow composer rather than spilling behind it.

Administration loads runtime policy, providers, browser targets, and groups independently. A failed resource has its own retry state; successfully loaded sections remain visible. Previously loaded data is marked stale when its refresh fails rather than silently appearing current.

The provider wizard advances one step at a time on Enter; it does not save an incomplete configuration. Blocked steps remain focusable and expose the fields that need attention. Protocol changes update untouched defaults without overwriting a customized endpoint. If storage is unavailable, the view starts wrapped and its toggle still works without persistence. ## Search workspace states and scope

Search names the current query and the effective corpus and filters. **Wiki** and **Saved offline** select the corpus; the separate **Filter from the current page** group displays the page's language and path before offering language and page-tree filters. Unfiltered online search is **All Wiki**. Selecting the already-active corpus does not clear filters. **Clear filters** keeps the query and corpus, broadens the search, and returns focus to the input; it is available in the filter group and scoped no-results recovery. Offline filter controls remain focusable with a visible explanation, but unapplied filters are never shown as active.

With fewer than two query characters, Wiki Search shows the current tab's working set and quick actions rather than inventing search results: up to five recent visits or successfully committed edits, followed by pins not already shown as recent (at most fifty pins). These are session-only page selectors, scoped to origin, installation, account and `authVersion`, not a synced collection or persisted content cache. Session storage contains IDs and scope only; titles, paths and visibility are fetched anew under current server authority. Unavailable storage falls back to memory, and the UI distinguishes loading, metadata failure, empty and unavailable-session/server states.

Identity invalidation retires selectors and pending metadata; unknown verification suspends display rather than treating it as logout. Initial direct-reader visits wait for verification and capture the newly established scope without mistaking that verification for page navigation; actual navigation, disposal and identity changes still retire the pending visit. Denied or missing pages are removed during hydration, and stale reads cannot repaint a later scope. Working-set links encode locale and individual path segments, preserving literal URL punctuation for ordinary and modified navigation. Pinning does not authorize a page, include it in an Agent request, or download it for offline reading; **Saved offline** remains its separate corpus.

Zero-query quick actions offer a draft-only question about the current page, permission-gated **Create page**, and **Browse by Tags**. Create opens the existing location selector without writing a page. Only a mounted reader supplies the current folder and page locale; elsewhere it starts at `new-page` with a supported UI locale (base-language fallback, then site locale). The seed is captured when opened so later navigation does not rewrite the selector draft. Current permission, connection and unsaved-work guards still apply.

Initial loading uses a full loading state. Query and scope refreshes retain previous rows and suggestions with their original query/scope context and unavailable actions. A failed refresh leaves those rows readable, clearly marks the failure, and offers retry rather than presenting the error as an empty collection. Fresh zero-results states show a truthful zero count, recovery choices, and one Agent draft action, not competing duplicate Agent buttons.

Online summaries distinguish returned rows, total matches, and bounded-window lower counts. Saved-offline summaries report matching saved pages; the separate hint reports how many saved pages were searched. Truncated downloaded results use a `+` lower-bound match count, not the size of the downloaded corpus as a match count.

Continuation cancels on a new query, retry, mode change, offline-session change, close, or unmount. Late responses and late cleanup cannot overwrite or stop a newer continuation. Appending pages preserves keyed rows, scroll context, selected result identity, and suggestion position. Errors retain loaded pages and offer **Search again** for expired continuation recovery. When the final continuation removes its focused button, focus moves to the newly added result or the input.

The Add Sources dialog transfers focus from a disappearing, keyboard-focused continuation button to the first enabled newly added checkbox, or back to its query input when nothing usable was added. The hidden native checkbox receives focus without native ancestor scrolling; only the results list scrolls to reveal its row, preserving the modal's visible contents. Cancellation, a replacement query/dialog, or an intervening user focus move prevents that transfer.

Cancel discards pending source additions without changing the current draft. Cancel and Apply return focus to the actual header or composer ring when it opened the picker; ordinary **Add sources** cancellation returns to that button, and its successful Apply returns to the composer.

Result titles wrap without truncation; descriptions remain bounded and paths wrap. Preview has a separate target rather than overlapping the result link. Below 600px, Preview moves beneath its row with a visible label and full touch target. The mobile header field is 44px tall with 16px text in a 52px extension; the Search overlay starts below that extension.

The Search panel is one continuous vertical scroller containing corpus controls, page filters, query context, results, Preview, continuation, and keyboard hints. Its content cannot flex down to zero height beneath fixed controls. Enlarged text and short or narrow viewports scroll the entire workspace instead of clipping results behind the scope area; controls remain in natural DOM/focus order, and keyboard-selected results scroll into view within the same panel.

Desktop corpus choices and the available page filters share a 40px-base toolbar. Narrow layouts and enlarged text keep controls in an intentional horizontal scroller; keyboard focus reveals the active control rather than leaving it clipped outside the viewport. Matching passages render as escaped text with amber marks and at most two visible lines, beginning near the first actual match. A metadata-only hit does not invent a body passage. Ask's hover/focus explanation remains draft-only; changing corpus or filters never sends a prompt.

Saved-offline rows omit the entire Preview cell and its unavailable-preview explanation. Their actual storage, locked-vault, capability and reconnect notices remain. Private cached reading uses normal vault setup, secret re-entry and unlock, followed by a current authorized snapshot save. Document navigation retires the in-memory key; unlock again in the saved-pages library before private Search can expose a row. The local row opens the admitted snapshot's exact page identity, source revision and rendered body, including while the browser is offline, without repairing it from the live wiki.

Private-vault verification must suppress automatic snapshots, screenshots, trace/video/HAR, API-value/protocol logging and session recording before the one-time secret appears and hold that boundary through cleanup. Inspect effective tool settings and the selected command's implementation; raw output mode alone is not capture suppression. Never record the generated secret or import authentication/keyring state. Restore the prior Search query, corpus, available filters and focus through normal controls, then retire only the owned disposable profile and fixture data.

## Search coverage and continuation

PostgreSQL search accepts authorized page identities before lexical, exact, fuzzy, and graph ranking caps. Current metadata and page rules produce those identities; protected pages qualify only through searchable metadata. Selected-page scope constrains both public and private candidate queries. Search results are rehydrated from current metadata before returning them. Exact page paths bypass unnecessary broader lexical/fuzzy matching.

Online content matches include a bounded passage from the currently authorized source revision. Metadata-only matches return no body excerpt; they do not invent a passage or expose protected content. Saved-offline search derives passages only from the current audience's authorized downloaded snapshots. Matching excerpts do not change ranking, result counts, cursors, or continuation bounds.

The browser requests 20-row pages from a bounded result window. Continuation keeps a five-minute snapshot of ordered identities, tied to the user session and query. It caches no page contents or excerpts. Each continuation reruns permission-aware retrieval restricted to the original numeric page IDs before ranking caps, then fills the next page from still-visible snapshot identities, preserving order across ranking changes and removals. New higher-ranked pages cannot displace the original tail. Snapshots are bounded to 128 process-local entries and expire across restarts; multiple replicas need instance affinity for continuation. An expired cursor asks the user to search again. Counts are explicitly lower bounds when the retrieval window is capped; scope and query refinement remain available.

Malformed explicitly supplied locale, path, cursor, or pagination values—including duplicate/array/object query forms—return HTTP 400. A well-shaped but invalid or expired continuation returns HTTP 409; neither case silently becomes a fresh search.

The permission prefilter currently reads scoped public metadata to evaluate the application's existing page-rule logic. This prioritizes one consistent authorization policy over a second SQL implementation. Large deployments should monitor whole-request latency and metadata volume; the included engine benchmark does not claim to measure that entire HTTP path. PostgreSQL is the sole maintained provider, and registry refresh rejects missing or unusable definitions before changing saved configuration.

Markdown page-link completion preserves public/private route identity and encoded path segments. Private destinations always retain their mandatory locale segment; public destinations follow the site's language namespacing. It consumes each matching cursor's own pre-existing closing parenthesis independently, including mixed autoclosing and pasted unfinished links, without skipping secondary cursors.

## Answers and changes

Completed answers offer **Copy answer with source links** and **Save as Wiki draft**. Saving opens an editable Markdown review with title, locale, path, and rendered preview; opening, preparing another draft, and closing do not write a page. **Copy reviewed Markdown** exports the edited review separately from the unchanged canonical answer export. The explicit **Create private draft** action creates a new private, unpublished page through the existing page API. It never overwrites an existing page, and creation errors preserve the reviewed content.

The review checks authorized earlier creations for that exact answer when opened. **Created while reviewing this answer** identifies origin, not an immutable match to the answer or a synchronized copy. Receipts distinguish the committed creation revision from the destination's current revision, current audience and publication state. **Open draft** uses only the currently authorized destination; a committed but unavailable destination exposes no old title, path or link. **Load more drafts** continues the receipt list, and **Refresh earlier drafts** performs another read-only check.

A creation attempt captures one request identity. If its response is lost or cannot be confirmed, the review blocks another submission and offers **Check creation status**, a read-only lookup that cannot create a duplicate. Unknown, missing, or inaccessible results never mean the attempt was rejected. A definite rejection allows a deliberately corrected new attempt; a confirmed commit offers **Prepare another private draft**, with a new destination suggestion and a new request identity on explicit creation. Multiple intentional drafts are allowed. Identity, permission, or answer-context changes cancel receipt reads and remove destination metadata; recoverable Markdown stays in memory for its owning account and answer, not in browser-persistent storage or another account's display. Reloading the document does not preserve unsaved review text.

Existing Agent edit proposals retain their immutable diff, revision checks, and approval controls. Mermaid source disclosures are closed by default and preserve each user's open/closed state when rendered output is refreshed.

Terminal assistant messages carry a bounded, owner-scoped `runOutcome` with terminal status and an optional error code; it does not keep a finished run in `currentRun` or expose provider error messages. Partial, failed, and cancelled answers retain truthful recovery states after reload. Review request restores an editable draft and never resubmits it automatically.

Governed changes report their recorded outcome rather than treating a mutation as an unanswered source question. Applied receipts identify the exact proposal and committed result; denied decisions identify the proposal that was not applied. These receipts establish operation status, not page-content facts. An unrelated missing fact can still make the answer partial without concealing a completed change. Missing or no-longer-readable page metadata is not proof that the page was deleted.

Transcript proposal diffs keep horizontal code scrolling local, but vertical wheel input can continue into the transcript at the diff's edge. Reading earlier messages must not trap the pointer inside a short diff or make the approval-navigation control unreachable.

Activity labels name the action and its status. Running or exceptional activity opens by default, while a user's native disclosure choice survives transcript updates. Completed message entrances are static; animation and decorative live indicators are confined to live work. Presentation caches retain unchanged entry identities and invalidate when content, locale, time, or origin changes.

## Token accounting and provider completion

Agent runs retain independently measured `inputTokens`, `outputTokens`, and provider-reported `totalTokens`. The total is a nonnegative safe integer at least the safely added directional values and is never derived from them; `totalTokens - (inputTokens + outputTokens)` remains an intentionally unclassified residual. It must not be presented as reasoning, cache, tool, or another invented category. Charged-token limits and settled reservation/daily/goal `consumedTokens` use the full total, while dispatch admission reserves a configured exposure bound once and never adds that hold to terminal measured usage; direction fields remain measured diagnostics.

Conservative cost applies the configured input and output rates to those directions and the higher rate to the unclassified residual, using a `BigInt` numerator and ceiling. That residual pricing and any classification-based refund apply only to a validated provider-reported receipt. If usage is omitted and estimated fallback is explicitly permitted, accepted directions and totals are estimates—not measured usage—and cost remains the full admitted max-rate exposure without a residual refund. New usage-bearing events use `usageVersion: 2` plus `totalTokens`; the outer agent-event envelope remains `schemaVersion: 1`. Immutable legacy events are accepted only when both fields are absent and their directional sum validates, yielding a lower bound rather than a reconstructed total. Invalid, mixed-era, and unknown-version payloads are rejected. Admission reserves whole-token exposure before dispatch; a valid complete receipt settles once with its full total/cost, releases only its original hold from reserved counters, and charges the full actual to consumed counters. Positive pending settlement blocks reclaim/expiry/cancellation release/top-up, and unavailable settlement remains conservative rather than reporting success.

## Validation and rollout

Token-accounting rollout is a coordinated **drain workers → migrate → deploy all nodes → restart** cutover with no mixed old/new writers. Drain and stop every agent-state writer before applying `tsepistle-000031-agent-total-token-accounting.ts`; its `agentRuns.totalTokens` backfill stores only validated directional sums as lower bounds and never rewrites quota-ledger history. Deploy the current writer to every node before restarting or restoring admission; see [Agent deployment and operations](agents-deployment.md) for the operator sequence.

**Validation scope.** Provider and workspace changes use focused component/store/API/host checks, applicable typechecks, lint, production builds, and bundle-budget checks. Ordinary media fixtures use SQLite; full-suite, native PostgreSQL, and large-PDF coverage are separate checks. Live provider execution and deployed browser flows supply behavioral evidence that unit checks alone cannot provide.
