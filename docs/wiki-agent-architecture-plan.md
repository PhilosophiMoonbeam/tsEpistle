## Decision and non-negotiable boundaries

Keep the existing trusted web-host runtime, not a coding-agent runtime transplant: authenticated conversation → durable coordinator → Ax-compatible provider service → admitted ActionKernel actions → revision-bound Wiki evidence → answer acceptance → durable publication and SSE. The inbound MCP server uses the same action kernel with API-key authority; it is not an outbound MCP client or an LLM provider. Preserve requester-scoped search rehydration and revision checks (`server/agents/actions/page-reads.ts:388-414,533-537`), permission/flag/live admission and side-effect fence (`server/agents/actions/kernel.ts:145-191,245-303`), reconciled accounting and bounded worker leases (`server/agents/coordinator.ts:1018-1051,1076-1084,1470-1547`), owner/cursor-scoped SSE replay with backpressure (`server/agents/sse.ts:283-405`). Do not reset usage, replay unaccounted provider calls, increase profile caps, switch the model, trust model text as authorization, or silently parallelize mutations.

**Content scope:** An unauthenticated fresh browser session loaded `/en/home`, and its Account menu offered **Sign in**; the rendered page included plaintext credential-like material. Do not reproduce it in diagnostics or this document. The user subsequently attested that the homepage is a synthetic representation and explicitly authorized reading it directly, so this earlier content concern did not block the authenticated live smoke. This does not independently establish whether every visible credential-like string is unusable outside the synthetic page. The observation concerns page content, not evidence that the Wiki Agent leaked credentials.

## Framework alignment

`package.json:80` and `bun.lock:10,332` now pin Ax **24.0.21**, matching the published npm version observed during review. `server/agents/providers/factory.ts:1094-1190` already selects Ax-native OpenAI Responses, OpenAI Chat and Anthropic, alongside a local Gemini Interactions implementation and a legacy completion adapter; `server/agents/providers/registry.ts:384-400` declares the limited legacy/prompt-tool capabilities. The local adapters implement the Ax chat service contract for different wire protocols, not demonstrably redundant replacements for Ax. Keep them until protocol-level conformance proves an Ax-native replacement equivalent. Ax's documented `ai()` factories support vendor and OpenAI-compatible services; that does not prove custom endpoints or Gemini Interactions conform. Official documentation: https://github.com/ax-llm/ax and https://context7.com/ax-llm/ax .

The split inbound MCP SDK now pins server/node/client **2.1.0** and express **2.0.1** (`package.json`, `bun.lock`). `server/agents/mcp.ts` retains split SDK registration and request-scoped admitted tools; official-client negotiation, API-key authority, Host/Origin rejection, approval and revocation checks pass against this family. The modern protocol rejects a POST without `MCP-Protocol-Version`. SDK currency does not establish outbound MCP connectivity or Ax/provider compatibility. Official SDK documentation: https://github.com/modelcontextprotocol/typescript-sdk . An outbound remote-MCP capability requires its own per-user authorization, egress/credential policy and client lifecycle decision; it is not established by the current inbound server.

Controlled synthetic measurement (25 accepted runs per shape; same fake provider, corpus and 300 reported tokens / 400 µcost per run) found 600 source rows with 12 citations at p50/p95 **681.66/697.50 ms** before the source-term prefilter and per-evidence lexicon cache, versus **42.67/47.29 ms** after both. Serialized provider input stayed 50,380 bytes; two provider turns, one retrieval and zero rejected drafts stayed unchanged. On in-memory SQLite, 100 idle claim checks measured p50/p95 **0.502/3.5 ms**, 100 owner-bound two-event retrievals **0.224/0.522 ms**, and 50 SSE cursor replays **0.31/0.517 ms**; these are not PostgreSQL, network or live-provider latency measurements. The deployed homepage run is a separate real-provider observation: eight answer drafts (seven rejected, one accepted), 267063 settled tokens and 326658 µcost; it is not a repeated p50/p95 comparison.

Do not introduce a second scheduler, new event protocol, filesystem memory store, unrestricted shell/browser tools, blanket retries, a general plugin system, broad chat UI rebuild or LangGraph migration without independent evidence. `server/agents/providers/engine.ts:4099-4121,4217-4238` already bounds turns and retries correction after rejection; additional loops spend tokens without proving citation validity. Existing `client/helpers/agents-api.ts:782-790` and `client/store/agents.ts` use cursor-aware EventSource reconciliation; preserve it rather than copy another chat transport.

## Verification and rollout

Use deterministic synthetic provider fixtures for protocol and counterexample checks, followed by consented real-provider samples with fixed profile/corpus. For each run, record success/partial/failure, substantive coverage and evidence precision, queue/provider/DB durations, emitted event sequence, exposure and settled token/cost; never mix estimated exposure bytes with actual token usage. Exercise two owners, two workers, cancellation, permission revocation, concurrent approvals, reconnect and lease expiry. Run changed-path tests and shared/server/client typechecks, build a committed revision, and deploy **only the application service** under `docs/agents-deployment.md`; preserve PostgreSQL, mounted Wiki data, identities, secrets and enabled capabilities. A health response or narrow citation fixture is not live proof. The exact homepage starter passed its authenticated deployed UI smoke on `94888b97`; the high correction count and absence of older run records observed before this smoke remain separately documented risks.
