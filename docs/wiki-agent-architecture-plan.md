## Decision and non-negotiable boundaries

Keep the existing trusted web-host runtime, not a coding-agent runtime transplant: authenticated conversation → durable coordinator → Ax-compatible provider service → admitted ActionKernel actions → revision-bound Wiki evidence → answer acceptance → durable publication and SSE. The inbound MCP server uses the same action kernel with API-key authority; it is not an outbound MCP client or an LLM provider. Preserve requester-scoped search rehydration and revision checks (`server/agents/actions/page-reads.ts:388-414,533-537`), permission/flag/live admission and side-effect fence (`server/agents/actions/kernel.ts:145-191,245-303`), reconciled accounting and bounded worker leases (`server/agents/coordinator.ts:1018-1051,1076-1084,1470-1547`), owner/cursor-scoped SSE replay with backpressure (`server/agents/sse.ts:283-405`). Do not reset usage, replay unaccounted provider calls, increase profile caps, switch the model, trust model text as authorization, or silently parallelize mutations.

**Content scope:** An unauthenticated fresh browser session loaded `/en/home`, and its Account menu offered **Sign in**; the rendered page included plaintext credential-like material. Do not reproduce it in diagnostics or this document. The user subsequently attested that the homepage is a synthetic representation and explicitly authorized reading it directly, so this earlier content concern did not block the authenticated live smoke. This does not independently establish whether every visible credential-like string is unusable outside the synthetic page. The observation concerns page content, not evidence that the Wiki Agent leaked credentials.

### First-line diagnosis and candidate flow

Before the compact-policy correction, the prompt asked the model to group adjacent page and section facts, while assessment required every cited factual clause to be supported by one source unit. That conflict was a plausible contributor to rejected drafts, not a proven cause of each failure; the corrected prompt now requires independently supported points. A prior private review found five second-draft numeric-integrity failures with the values preserved but punctuation or adjacent modifiers altering significant-word segments. Those remain candidate false rejections until each clause and intact source unit is adjudicated: matching values somewhere in a section do not establish the same subject, unit, or qualifier assignment, and the first draft's subject mutation must still be rejected. Correction remains bounded to ten displayed issues, four feedback fragments, three units per fragment, and 1,200 serialized characters. Do not weaken the validator or attribute the earlier trace to parser, model, context repetition, or transport without evidence.

Keep the existing graph: authenticated request → coordinator/profile admission → intent/scope/context plan → admitted read → revision-bound evidence view → model synthesis → assessment → accepted publication. The plan and evidence view are run-local extensions of existing engine state, not a scheduler, store or mandatory extra model call. A small `ContextPlan` records intent, requested facets, scope and temporal target, candidate/read references, per-facet state (supported, unread, conflicting, unavailable or budget-limited), and reservations under the admitted profile. The model supplies semantic facet selection and answer wording during ordinary work; the host supplies authority, scope, limits, read receipts and observable coverage, never answer sentences.

Extend the existing `CitationEvidence` / `CitationSourceUnit` path (`engine.ts:1017-1119`) with an internal `EvidenceUnitRef`: run/read action, page, exact source revision and optional version, section and deterministic unit identity. A bounded evidence view carries exact source text, structural context and source location, separately marking authorization/read success, provider delivery and current prompt residency. Use the same canonical unit extraction for what synthesis sees and assessment validates; omitted or merely retrieved content is ineligible. Keep sources intact rather than slicing facts, state unresolved facets, and make candidate metadata from search/discover/related distinct from read evidence (`engine.ts:115-120,977-1037`). Typed model-authored claim blocks—facet, exact prose and unit references—are a later optional arm. For every arm, the model authors the answer; the host validates bindings and may render citation markers, but never invents, paraphrases, removes or reassigns answer content.

Ownership stays explicit: page actions own requester-authorized reads and revision identity; the engine owns selection, delivery/residency, assessment and bounded correction; coordinator/orchestration owns scheduling, budgets and durable work; provider adapters own wire translation and measured dispatch; the existing projection/UI owns safe progress. Frozen host-selected scope is an additional restriction, separate from live principal authorization: use stable page IDs for selected scope and canonical resolved metadata for locale/path; never infer scope from model prose. Apply one predicate to direct current/version/OKF reads, discovery, recent/related/history/link/patch results, cached or recovered results and child evidence, then recheck identity at evidence delivery. Filter candidates before hydration/top-k/totals and return a scoped limitation rather than silently widening; do not reveal excluded titles/content in errors. Current code applies selected IDs in `pages.search` (`page-reads.ts:380-397`), while `pages.discover` forwards its input without visible selected-scope injection (`page-reads.ts:486-495`); the inspected `get`/`getVersion` handlers use requester authority but show no selected-context membership check (`page-reads.ts:533-537,636-653`). The observed run was all-Wiki and establishes no scope incident. The ActionKernel refreshes live admission on action execution (`actions/kernel.ts:260-275`); its SHA-256 authority digest is unkeyed, not a signature (`actions/kernel.ts:129,172-203`).

Identity and reuse are separate correctness gates, not recipe-run findings. Current citation IDs encode page plus revision (`page-reads.ts:244-255`); `getVersion` changes the citation URL without qualifying that ID (`page-reads.ts:636-650`), and historical `getOkf` carries a version ID while its citation remains page/revision keyed (`page-reads.ts:539-572`; `server/agents/okf.ts:112-130`). A read-only DB check on 2026-09-25 found one `(pageId, sourceRevision)` group with three historical versions and two distinct content texts. The proposed, not-yet-shipped identity contract retains `page:<id>:revision:<revision>` for current evidence and uses `page:<id>:version:<versionId>:revision:<revision>` plus a section suffix for historical evidence; citation-marker syntax stays unchanged. Carry that identity through page/section citations, historical OKF, links/excerpts, registry, child packets, provenance and correction. Registry insertion must reject an incompatible binding (page, version, revision, exact scope/representation or citation target) rather than overwrite; a repeated identical binding may add a read receipt. Recent excerpts, full Markdown and OKF cannot silently widen one another's support. Use source actually retrieved, not a stored hash alone, to distinguish content. Do not alias old historical markers or rewrite accepted messages. This is a reachable identity-alias shape, not a recipe collision, exploit or cross-owner leak.

Root evidence seeded from child work must be tied to exact source units available and delivered in the root prompt, not packet prose alone (`engine.ts:124-126,4031-4044`). The run-local `pageReadCache` may reuse a result without invoking the action again and reports the original action call (`engine.ts:4031,4731-4786`); a hit is reuse, not fresh verification after permission or page changes, and must retain its receipt. These identity/scope constraints are prerequisites for selected-scope, multi-version or expanded reuse/cross-task evidence views—not causes of the recipe trace. A narrower all-Wiki/current-source prompt or instrumentation trial need not wait if it does not encounter or amplify them and makes no wider guarantee.

The earlier assessment blocked unsupported cited clauses but recorded uncited prose only as a grounding warning. A live recipe answer still published an uncited opening, so the first structural gate blocked substantive prose discarded before a later citation. A held-out comparison then published factual prose and list items after the last citation, still only warning. The revised presentation contract blocks substantive uncited prose both before a later citation and after the last citation in an otherwise cited answer, except for an explicit final `## Recommendations` section reserved for original advice. Standalone uncited advice remains permitted. Section shape cannot prove semantic truth: factual claims disguised as advice remain a limitation and must not be declared grounded. The client still displays a generic “Preparing a response” announcement except for terminal/approval states and collapses tool activity in `<details>`; the correction phase and elapsed wait are not separately represented.

### Applied run-local evidence and observability contract

The implementation uses the existing action session, engine and durable event path; it does not add a scheduler, memory store, provider abstraction or database migration. Frozen `knowledgeContext.scope` is an additional host restriction on enumerations and direct/current/version/OKF reads. Selected scope uses page IDs; locale and section scope resolve canonical page metadata before applying limits or totals. Live requester permissions remain independently required, including for version history. Historical citation IDs include the exact version ID and revision; current citation IDs keep their existing form. A later read with an incompatible representation cannot silently replace the first citation binding. A verified current `listRecent` opening excerpt may promote to a full Markdown representation only for the same page, revision, path, title and exact prefix after a successful full read; the excerpt itself never proves unread suffix facts.

The engine tracks per-read source units with structural context and immutable representation identity. Only units actually delivered to a provider request can support that request's citations. Large child reads enter the root through bounded complete units rather than full background pages; compaction reentry is restricted to previously delivered units with a fresh authorized receipt and a bounded context envelope. Recovered, reused, child and correction evidence is checked before replay, and stale results are replaced by a generic unavailable result. Search/discovery/related metadata and undelivered results remain leads, not citations. The run-local context plan retains the request, source scope, selected IDs, model-planned task facets, unknown temporal target and current reservations; its facet counts are observations, not a source of authorization or host-generated answer sentences.

Use one `pages.listRecent` for a basic recent-items recap; explicit tag, path, lifecycle/taxonomy, or browse requests may use their corresponding admitted actions. For other content questions, read an exact current page or requested historical version directly with the admitted action; otherwise start with one distinctive targeted `pages.search`. Explicit user-provided page/version IDs may direct a read only when admitted; user wording grants no authorization and missing IDs must not be inferred from candidate labels. Provider-only observational discovery returns `outcome`, bounded returned/new/repeated candidate counts, continuation, and coverage; it is never citation evidence. Distinct candidates compare `(pageId, sourceRevision)`, not semantic novelty; a bounded no-match does not establish Wiki absence. Follow up only for a specific unresolved facet, useful reported pagination, changed targeted query, taxonomy/path discovery, or related-link traversal within budget. Do not impose fixed search-count limits or stop solely because candidates repeat. Report denial, ambiguity, capacity, and partial coverage without broadening scope; cite factual clauses from exact source-local evidence and identify authorized historical versions. Substantive prose before a later citation or after the last citation in a cited answer is blocked unless the latter is original advice within an explicit final `## Recommendations` section; standalone uncited advice is not automatically rejected. One matched run is directional and cannot establish the proposed p95 cost/latency criterion.

### Generalized run-local action execution (2026-09-25)

For source-bearing Wiki reads, the engine separately tracks canonical output, exact delivered provider messages, current prompt residency, original read receipts and fresh authorization/revision verification. ### Cross-provider cache-aware accounting and prefix policy (2026-09-26)

The provider factory derives cache eligibility from the exact official HTTPS base URL, transport and model; a compatible hostname or provider-looking model name alone is not evidence of provider-side caching. The current policy is:

| Transport | Cache behavior | Full-input normalization and prefix policy |
| --- | --- | --- |
| Official OpenAI Responses / Chat | Provider-managed implicit prompt caching; no GPT-6-only explicit cache options on the configured `gpt-5.6-terra` model. | Ax reports uncached prompt tokens separately from cache reads/writes; add both to full input once. Preserve the root prefix for recognized cache-capable official models. Apply the 1.25× cache-write allowance on GPT-5.6 and later. |
| OpenResponses-compatible | Endpoint-specific caching is unverified; no OpenAI-only request options or pricing assumptions. | Normalize Ax's separate cache counters when supplied; retain ordinary root compaction. |
| Official Anthropic Messages | Set top-level automatic five-minute ephemeral `cache_control` in the existing request wrapper; do not enable it on custom base URLs. | Reconstruct full input from uncached, cache-read and cache-creation tokens. Preserve the root prefix and apply the 1.25× cache-write allowance. |
| Gemini Interactions | Existing implicit cache behavior; no new explicit cache resource or persistence. | Report validated `total_cached_tokens` through Ax's cache-read field without adding it again to Gemini's already-inclusive input. Preserve the root prefix only on the recognized official endpoint. |
| Legacy Completions | No assumed cache feature. | Preserve supplied independent total tokens; reject malformed usage and never synthesize zero usage when the provider omitted it. Keep ordinary root compaction. |

Eligible **root** runs retain the stable system instructions and canonical conversation history before run-specific page, activity and knowledge context, now carried as a labeled active user message. They bypass only the opportunistic approximately 75%-full turn-boundary history summary; approximately 90% capacity/headroom, forced summaries, child-run compaction, authorization/revision rechecks, exact-source validation and evidence gates remain in force. The six transports continue to reserve and settle **full** input/output/total tokens for quotas, including residual reported tokens. On official Anthropic and GPT-5.6+ OpenAI, conservative cost also prices *all* input at the 1.25× write rate (including eventual reads) and residual tokens at the higher applicable rate; no speculative cache-read discount or historical-event rewrite.

`cachedInputTokensReported` and `cacheCreationInputTokensReported` on a completed model turn or compaction receipt are nullable diagnostics, not amounts subtracted from quotas. A number means observed through the adapter; `null` means unavailable, **not** a reported cache miss. Pinned Ax drops raw OpenAI cache counters when they are zero, so raw zero and omitted counters both appear unavailable in that path; positive reads/writes are preserved. Explicit Gemini/Anthropic zero remains zero. Cumulative stream snapshots cannot decrease observed canonical counts or previously observed cache counters, and a later omitted cache counter does not masquerade as a newly reported zero. Existing Gemini's 23 zero-hit reports are historical observations, not evidence that every provider or prompt length will achieve caching. External provider billing and hit rates require separate provider-side confirmation.
