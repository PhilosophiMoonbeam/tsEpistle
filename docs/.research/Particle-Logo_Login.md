## 1. Decision and non-goals

The prior interpretation as a fixed **Indigo Signal Field** was wrong. There is exactly one active branding source: the one image uploaded in tsEpistle Admin. A successful candidate drives both the ordinary site logo and one personalized login particle treatment in light and dark themes. The login treatment is decorative and never participates in authentication.

The Admin General page (`/general`, `manage:system`) provides one dedicated logo upload. The upload is processed automatically and asynchronously. The previous active ordinary logo and effect remain visible while processing and on failure; the new ordinary logo and effect activate together only in one successful, fenced transaction. Existing URL-only or default `logoUrl` values migrate unchanged and remain static-only until replaced. The server never fetches an arbitrary URL. There is no separate tsEpistle particle fallback.

The large field is optional decoration, not a replacement for `.login-brand`, `siteConfig.logoUrl`, `siteConfig.title`, or `#login-site-title`. Mobile, coarse-pointer, short-viewport, and insufficient-space layouts omit only the large field; the ordinary full-canvas logo remains visible inside the framed `.login-logo` credential-card container. Reduced-motion eligible desktop users receive the personalized static effect, without WebGPU/WebGL or animation.
Terminal ordinary authentication success may show a decorative TS Epistle open-book illustration in the login loader for a 900 ms opening sequence before redirect. The illustration is not shown for failed authentication, TFA, password-reset, verification, or other non-terminal states. Reduced-motion styling collapses the book animation without changing the success-only gate, and the artwork never participates in authentication.

## 3. Admin API, database authority, and transactions

### Upload and status API

Add dedicated `manage:system`-only endpoints: `POST /_api/site/logo` accepts exactly one multipart image and never accepts a URL; `GET /_api/site/logo` returns current active and candidate status; `POST /_api/site/logo/retry` retries the current failed candidate. Authorization occurs before multipart acceptance. Enforce a fixed `5,242,880`-byte source ceiling even when generic upload limits are larger. Admin General uses a dedicated one-file picker/drop target, not the generic media browser or `POST /u`, and states that pipeline 7 publishes the ordinary `logo-png` for login, navigation, and email plus separate icon/ICO URLs for favicon and PWA surfaces, alongside the personalized effect when available. Remove `logoUrl` from the ordinary General save payload so an old open form cannot overwrite activation; retain the existing managed-config fence and safe status/retry behavior.

Upload returns `202` with a revision/status URL when work is needed, or `200` when an existing ready revision is activated. The no-store status response exposes only safe error codes (`UNSUPPORTED_IMAGE`, `IMAGE_TOO_LARGE`, `INVALID_IMAGE`, `NO_VISIBLE_PIXELS`, `UNSUITABLE_LOGO`, `PROCESSING_FAILED`, `ARTIFACT_TOO_LARGE`) and shows the still-active preview plus candidate state: Uploading → Processing → Active or Failed. Raw decoder errors and stacks remain server logs with job/revision IDs. Retry does not alter the active revision.

### PostgreSQL schema

PostgreSQL is authoritative; local files are an optional atomic read-through cache keyed by the composite `(kind, final content hash)`.

- `siteLogoObjects`: immutable blobs keyed by composite `(kind, sha256)` of actual bytes; `kind` is exactly `source`, `logo-png`, `icon-png`, `favicon-ico`, `particle-v1`, or `effect-static-png`. A ready pipeline-7 revision publishes one ordinary `logo-png`, seven `icon-png` files (`favicon16`, `favicon32`, `tile150`, `apple180`, `app192`, `app512`, and `maskable512`), and one `favicon-ico`; `particle-v1` plus `effect-static-png` are an optional enhancement pair. Browser icon files are separate from the ordinary logo: `favicon16`/`favicon32`, ICO, `app192`, and `app512` are transparent, while `tile150`, `apple180`, and `maskable512` are opaque. Source is private; only complete derived objects are public, and no theme-specific, backplate, or on-demand-composited object exists.
- `siteLogoRevisions`: UUID, source hash, integer pipeline version (new candidates use `SITE_LOGO_PIPELINE_VERSION=7`; v1-v6 are historical), `pending | running | ready | failed`, durable job ID/retry sequence, ordinary-logo and complete browser-icon/ICO hashes, optional enhancement hashes (`particle-v1` and `effect-static-png`), revision metadata columns `normalizedWidth`, `normalizedHeight`, `particleCount`, and `medianStroke` (nullable before a ready enhancement), plus nullable validated `auraColor`, safe error code, requester, and timestamps. `aspect` is derived as `normalizedWidth / normalizedHeight`, never stored as a second authority.
- `siteLogoState`: one installation-global row with monotonic generation, `desiredRevisionId`, and `activeRevisionId`. Foreign keys prevent deletion of desired/active data and use the expected object kind with each hash. Status reports desired state; serving uses active only.
- Source identity uses actual source-byte SHA-256; every derived object hash is computed from its final bytes, never from a logical path, source path hash, or revision ID. Every foreign key and database/object lookup supplies and validates both the expected role/kind and hash; a hash match with the wrong role is invalid.
Treat a stored object as immutable only while its bytes verify the declared `(kind, sha256)` identity. A hash/content mismatch is integrity corruption, not a valid immutable value: lock the singleton, object row, and referencing revisions before recovery; valid object rows are never mutated.
- Keep `settings.logoUrl` byte-for-byte for legacy compatibility. Unmanaged installations retain the exact legacy/default value. Managed activation writes the immutable public `logo-png` URL for login, navigation, and mail in the same transaction as `activeRevisionId`; pipeline-7 favicon and PWA surfaces resolve their separate icon/ICO descriptor rather than reusing `logoUrl`.

The upload/source/revision/job enqueue occurs in one transaction using `DurableJobStore` and the existing Knex transaction. Lock the singleton state. DB failure rolls back all four effects; do not mutate `WIKI.config` before commit or use unchecked `saveToDb` return as commit protocol. Before any same-source shortcut, validate the active source, ordinary logo, complete icon/ICO family, and any present enhancement objects by expected composite `(kind, sha256)` identity and by hashing their stored bytes. If any active object is missing or mismatched, preserve `activeRevisionId` and its existing URLs, never return `ready`, and enqueue fenced repair candidate work; derived objects not yet staged are expected while processing.
### Handler protocol rollout and rollback

The handler protocol is distinct from the `particle-v1` binary wire format. Historical pipelines v1-v6 use legacy protocols `process-site-logo@1` through `@4`; current pipeline 7 uses `process-site-logo@5`. Capability-aware claiming filters by the worker-advertised protocol before lease ownership, so an older worker cannot claim pipeline-7 work. Historical paired terminal revisions remain replay/no-op or fail-safe compatibility cases; only the current `@5` handler reads source, runs pipeline 7, and publishes current outputs. This ordering is a release requirement, not a claim that deployment or live activation has occurred.
For a mismatching object row, corruption recovery locks that row and every referencing non-active revision, atomically quarantines/deletes or marks each non-active reference retired before replacement work, and never leaves a ready row pointing at corrupt bytes. If an active source or derived row is corrupt, it is not deleted out from under the active pointer: the active pointer remains authoritative and is not cleared while unaffected valid surfaces continue serving; a fenced repair candidate stages replacement outputs privately. Its publish transaction may replace that mismatching row in place only with bytes whose SHA-256 equals its declared `(kind, sha256)` (or insert the missing row), atomically restoring all references; public reads remain `404` for the mismatching object until that commit. A repair or same-byte retry is idempotent under the same singleton/object locks, and valid rows are never rewritten.

Retire superseded revisions without mutating their objects. A daily durable cleanup takes the singleton lock, rechecks that a retired revision is still neither `activeRevisionId` nor `desiredRevisionId` and has remained retired for at least 37 days, then atomically deletes that revision row and any now-unreachable source/derived objects in the same transaction; no ready row survives object deletion for later reuse. Active and processing sources/bundles are never age-deleted. Failed desired revisions remain retryable for 37 days; cleanup may clear `desiredRevisionId` and delete that failed revision and its now-unreachable objects in the same lock-and-recheck transaction. Durable-job history may expire independently, so revision status cannot require a permanent job foreign key.

The current durable handler reads source bytes from PostgreSQL, never HTTP, local cache, uploads, or storage. Capability-aware claiming filters by the worker-advertised protocol before lease ownership, so an older worker cannot claim pipeline-7 `process-site-logo@5` work. Derived insertion is idempotent. Before inserting or publicizing a candidate bundle, measure the final ordinary logo, browser icon/ICO, optional enhancement, binary raw, and gzip-9 bytes against §8; an oversize candidate is marked failed with `ARTIFACT_TOO_LARGE`, leaves no derived public objects or URLs, preserves the old active revision, and publishes nothing. Publication locks the job and singleton state, verifies the exact running lease owner/token and an unexpired lease, and checks budgets before insertion.


## 4. Input validation and automatic processing

Initial managed formats are static PNG, JPEG, and WebP. Reject SVG, GIF/APNG, AVIF/HEIF, TIFF, PDF, multipage or animated inputs, corrupt/truncated/polyglot or MIME-spoofed data, and decompression bombs. Existing SVG and external URL logos remain valid static legacy values only. Hash actual bytes; ignore filename, extension, and claimed MIME for identity/type. Source bytes must not exceed `5,242,880`.

After format validation and EXIF orientation, require each dimension `64..4096`, total pixels `<=16,777,216`, at most four channels, and visible pixels. Use Sharp `0.35.4` with `failOn: 'warning'`, `limitInputPixels: 16_777_216`, `limitInputChannels: 4`, `unlimited: false`, `autoOrient: true`, metadata inspection, sRGB RGBA normalization, and no enlargement. Accept a static input when `(metadata.pages ?? 1) === 1`; reject a reported page count `>1`, validate `pageHeight` only when present and inconsistent with a single frame (`pageHeight !== metadata.height`), and retain explicit animated-container rejection rather than silently selecting a first page. The particle pipeline version changes whenever particle normalization, masking, sampling, encoding, or artifact schema changes; those particle-only version refinements do not alter the ordinary canonical branch.

Use native alpha when present. For opaque inputs, the particle/static branch alone may conservatively estimate a matte from a 3%-short-axis edge band clamped to `2..24` px: near-neutral means OKLab chroma `C <= 0.03`, and the matte is the component-wise alpha-weighted median OKLab of qualifying edge pixels (weight = source alpha). Use 8-connectivity for edge-connected clusters and mask components. Remove only a cluster with at least 85% total-border membership and at least 70% membership on each edge at OKLab delta `<=0.035`; for distance `d` from the matte, retained alpha is `0` at `d <=0.035`, linear `(d-0.035)/0.035` for `0.035<d<0.070`, and unchanged at `d >=0.070`. If constraints fail, preserve a genuine full-bleed badge and do not remove its background. When removal is attempted, retained-alpha fraction is `sum(generated alpha) / (255 * pixelCount)` and must be `>=2%` and `<=85%`; a meaningful connected component is one with at least `0.25%` of original alpha mass, and its disappearance rejects the mask. Trim only transparent/removed-matte padding, never foreground; deterministic normalization and the exact 4% per-side internal source padding apply only to the particle/static branch.
First decode accepted JPEG/PNG/WebP after auto-orientation to canonical sRGB RGBA raster `C`. The ordinary `logo-png` branches from validated `C` before every particle transform and is encoded losslessly as the full-canvas canonical upload appearance, preserving canvas, source colors, alpha, and aspect. The particle/static branch alone may apply the validated matte decision, transparent trim, linear-light premultiplied downsampling without enlargement, deterministic 4% padding, and source-alpha sampling. Let `componentCount` be meaningful 8-connected components, `occupancy=sum(alpha_i)/(255*pixelCount)`, and use `N=min(8000,max(2000,roundHalfAwayFromZero(8000*sqrt(occupancy)),8*componentCount))`. Pipeline 7 generates `N=2,000..8,000` records with eight deterministic reserved samples per meaningful component. Static and animated presentation preserve the core two-thirds quality target; full reconstruction remains required at IoU `>=0.75`.

The full-canvas ordinary `logo-png` is the lossless canonical `C` output defined above. The browser icon/ICO family is separate and uses the pipeline-7 transparent/opaque split; the particle/static raster alone retains deterministic 4% padding and any validated matte removal/trim. Pipeline 7 uses deterministic sampling with eight reserved samples per meaningful connected component, generates `N=2,000..8,000` records, and requires reconstructed-mask IoU `>=0.75`; the exact fixed vector is recorded, and an estimate is not a substitute.

Run preprocessing with concurrency one per process. A durable-job abort signal does not cancel native libvips work or bound RSS; release gates therefore measure each fixture in an isolated fresh child, recording absolute child `maxRSS` and wall time bound to that exact fixture's SHA-256 and source byte length. Cumulative RSS sampling across a reused worker is not valid evidence. Never claim an in-process Promise timeout cancels native work. Sharp is a production dependency only after final Alpine x64/arm64 (musl >=1.2.5; x64 SSE4.2), non-root Bun 1.4 fixture gates, optional dependency preservation, exact dependency policy, supply-chain review, and Sharp Apache-2.0 plus bundled libvips prebuild LGPL-3.0-or-later license/notice review pass. If those gates cannot establish bounded in-process operation, the implementation must use a killable resource-bounded subprocess before release.

## 6. Descriptor, binary, and public delivery

HTML, navigation, mail, and site-config resolution use one central PostgreSQL-backed resolver that overlays active branding rather than trusting process cache or NOTIFY. A ready pipeline-7 snapshot includes the ordinary `logo-png`, a separate browser-icon descriptor with seven icon PNG URLs plus one ICO URL, and an optional `logoEffect` descriptor with particle/static URLs and metadata. The ordinary `logo-png` URL and bytes remain identical on login, navigation, and mail; favicon and PWA surfaces use the separate transparent/opaque icon split. Legacy snapshots contain only the unchanged ordinary logo.

Expose the effect descriptor as `siteConfig.logoEffect`: `null` unless an active managed revision has a complete enhancement and its `pipelineVersion` is an integer in the currently supported range `1..7`; otherwise it contains required `pipelineVersion`, immutable `logoUrl`, `particleUrl`, and `staticUrl`, `width`, `height`, `aspect`, `count`, `medianStroke`, and optional `auraColor`. `siteConfig.logoUrl` remains the ordinary-logo compatibility field. The active resolver reads and validates the exact pipeline version plus enhancement metadata directly from the active revision row, derives descriptor `aspect === width / height`, and cross-checks descriptor dimensions/count against the parsed `particle-v1` header. Invalid or unknown future versions fall back to ordinary legacy branding rather than attempting the particle effect.

The particle binary is v1 little-endian and exactly 56 bytes of header followed by one payload of exactly `12 * N` bytes; therefore `fileLength = 56 + 12*N` and no trailing bytes are valid. The complete header layout is:

| Offset | Type | Field and encoding |
|---|---|---|
| `0..3` | 4 bytes | Magic ASCII `TSEP` |
| `4` | `u8` | Version `1` |
| `5` | `u8` | Flags exactly `0x07`: sRGB (`0x01`), Y-up (`0x02`), and straight alpha (`0x04`) are all required; every other value is invalid |
| `6..7` | `u16` | Header length, exactly `56` |
| `8..11` | `u32` | Width in normalized source pixels, `2..4096` |
| `12..15` | `u32` | Height in normalized source pixels, `2..4096` |
| `16..19` | `u32` | Particle count `N`, `2,000..8,000` for generated pipeline-7 artifacts; parser accepts `1..16,000` as its performance cap |
| `20..23` | `u32` | Payload length, exactly `12*N` bytes |
| `24..27` | `u32` | CRC-32/ISO-HDLC of payload bytes only |
| `28..31` | `u32` | XY block offset, exactly `56` |
| `32..35` | `u32` | Depth block offset, exactly `56 + 4*N` |
| `36..39` | `u32` | RGBA block offset, exactly `56 + 5*N` |
| `40..43` | `u32` | Size block offset, exactly `56 + 9*N` |
| `44..47` | `u32` | Seed block offset, exactly `56 + 10*N` |
| `48..51` | `u32` | File length, exactly `56 + 12*N` |
| `52..55` | `u32` | Reserved, exactly `0` |

Payload blocks are contiguous and typed as XY `Int16` (`4*N` bytes), depth `Int8` (`N`), source RGBA `Uint8` (`4*N`), size `Uint8` (`N`), and seed `Uint16` (`2*N`), all little-endian where multi-byte. Records are in ascending original source-pixel order and retain source RGBA with straight alpha; producers use pipeline-7 deterministic eight-reserved-samples-per-meaningful-component generation in `2,000..8,000`, while the parser accepts `1..16,000` only as its hard performance ceiling. Validate sentinels, dimensions, exact block offsets and lengths, 64-bit-safe arithmetic, CRC-32/ISO-HDLC, file length, and no trailing bytes before allocating geometry. This 12-byte source-record format is distinct from the runtime cloud-motion attribute: motion is a source-order vec2 (`8*N` bytes, 128 KB at `N=16,000`) updated through the shared instanced geometry.
The renderer submits one indexed instanced quad draw for all `N` sprites, producing `2N` indexed triangles. Native WebGPU is the primary backend. A deliberate WebGL2 request uses `WebGPURenderer`'s strict WebGL2 mode; `auto` accepts native WebGPU or only a successful built-in WebGL2 fallback. The TSL material emits direct sRGB with `premultipliedAlpha:false` and `NormalBlending`; the renderer uses `SRGBColorSpace` and `NoToneMapping`, and its `premultipliedAlpha:true` canvas is natively composited source-over the login backdrop.
Mount anonymous `GET` and `HEAD /_site-logo/:sha256/:role.:ext` before the common page/asset catch-all. Allow `logo.png`, `icon.png`, `favicon.ico`, `particle.bin`, and `effect.png` roles/extensions; require canonical lowercase 64-hex SHA-256 and never expose `source`. Resolve and authorize by the composite `(role/kind, sha256)` key, verify the stored bytes' SHA-256 and requested role before serving PostgreSQL bytes (optionally read-through cached by the same composite key), with exact `Content-Type` and `Content-Length`, strong digest ETag and conditional `304`, `X-Content-Type-Options: nosniff`, and `Cache-Control: public, max-age=2592000, immutable`; never vary on Cookie. Unknown, malformed, source, cross-role, traversal, or digest/content mismatches return `404`.

Hash URLs are immutable: replacement changes every active URL and needs no invalidation; old URLs remain identical during retention. Never overwrite same-path artifacts, use query-only cache busting, or key by mutable `assets.hash`. The route is independent of Guests `read:assets`, ACL/page protection, and sessions. No external fetch is permitted in processing or delivery.

## 7. Loading, fallback, accessibility, and cleanup

`LoginParticleLogo.vue` is synchronously imported by `client/components/login.vue` and has no static TresJS/Three import. It renders the static host and lazily imports `LogoParticleScene.vue`; authentication never waits. States are `omitted`, `static`, `loading`, `ready`:

- `omitted`: hard gate false; no field, import, request, renderer, loop, timer, or pointer listener; authentication is fully usable.
- `static`: active personalized static rendition is visibly present when available; otherwise the ordinary `.login-brand` is visibly present.
- `loading`: the active shared ordinary logo and personalized static rendition remain visibly present while import, backend capability/init, descriptor/binary fetch, parse, compile, and first frame run.
- `ready`: first successful nonzero-size particle frame commits; the static rendition is retained below canvas until that frame, then canvas may fade in. Every named pre-ready failure and every ready/context failure synchronously leaves or restores the visible personalized static image; if that image is missing or corrupt, the shared ordinary logo remains visible and authentication remains usable.

A 1,500 ms wall-clock epoch deadline covers lazy import through first frame; no Promise timeout is described as native cancellation. Fail on import rejection, Vue descendant setup/render exception, unsupported backend or failed strict-native selection, invalid URL/origin/CORS/non-2xx/oversize/unreadable response, parser failure, zero size, renderer/TresCanvas error, material/TSL error, loop exception, timeout, or device/context loss. Each callback/promise carries an epoch token; late completion cannot change state or authentication. Hard-gate loss tears down and omits; terminal failure, unmount, and reduced-motion transition retire/dispose the scene and renderer. Visibility/offscreen activity pauses rendering while retaining the current canvas, renderer, and lifecycle; resume continues that same generation when visible.

TresJS owns the canvas; the scene uses `TresCanvas` with transparent background, `clearAlpha=0`, antialias off, DPR `[1,1.5]`, and loop active only for animation. A caller-owned renderer factory creates `WebGPURenderer`; native WebGPU is primary, strict WebGL2 is deliberate, and `auto` accepts only a successful built-in WebGL2 fallback. Use `useLoop().onBeforeRender`, `shallowRef` for Three objects, one immutable source-attribute set plus one dynamic source-order vec2 motion attribute, one indexed instanced quad, and explicit disposal. Set direct-sRGB output (`outputColorSpace=SRGBColorSpace`, `toneMapping=NoToneMapping`), `premultipliedAlpha:false` on the material, `premultipliedAlpha:true` on the canvas, and handle renderer diagnostics/device loss through the backend lease.

Decorative host/image/canvas use `aria-hidden="true"`, `alt=""`, no role/focus/live region/tooltip, no keyboard handling, and `pointer-events:none` on canvas. Pointer input is passive primary mouse/pen on the bounded wrapper only; ignore touch/coarse/non-primary input, do not capture or prevent default, and do not log or transmit coordinates/timing.

Host lifetime retains media, visibility, free-space `ResizeObserver`, and `IntersectionObserver` monitors until host unmount. Scene-epoch teardown clears timers/listeners/hooks, stops and unsubscribes loop, aborts fetch, detaches callbacks, unmounts TresCanvas, retires/disposes the backend renderer, disposes geometry/material/resources exactly once, and releases refs. Hard-gate loss, terminal failure, reduced motion, and host unmount tear down and dispose; hidden/offscreen visibility pauses the existing scene/canvas/renderer without retiring it, then resumes through the same backend generation.
Reduced-motion startup is evaluated before any lazy import and therefore has a zero-ever resource trace. The runtime `false→true` preference toggle begins after animation has imported and acquired its resources; it shows the personalized static image immediately, then synchronously performs the scene-epoch stop/removal/disposal, with no post-toggle callbacks or fetches and no re-import, while authentication remains usable.
