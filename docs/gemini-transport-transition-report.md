# Gemini chat transport: deferred Ax-native transition

**Assessment:** 2026-09-27, repository revision `7e50ba2ec0e4`, installed `@ax-llm/ax` 24.0.24. **Decision: defer the cutover.** This is a future-review report, not authorization to disable Google Search, change provider profiles, migrate stored state, or deploy a new transport. Recheck the installed Ax version, Google's current documentation, and the product decision about Search before acting on it.

## Conclusion and scope

If Wiki retires **new** Google Web Search calls, no current Wiki chat feature has been shown to *require* the Interactions API rather than Google's `generateContent` API. Interactions' ordered steps simplify preserving mixed built-in Search and Wiki-function context, but [Google documents an opt-in `generateContent` equivalent](https://ai.google.dev/gemini-api/docs/generate-content/tool-combination). Without Search, native functions, Gemini 3 thought-signature replay, stateless conversation, streaming, and Files API references remain possible through `generateContent`. Google [recommends Interactions for new development](https://ai.google.dev/gemini-api/docs/interactions-overview) and says future features launch there; `generateContent` remains fully supported. That recommendation is a forward-compatibility consideration, not proof that Wiki uses an exclusive Interactions capability today.

This is **not** a finding that the *installed Ax provider* is ready for a constructor swap. Ax 24.0.24 currently has observable non-Search gaps in Wiki action schemas, configured thinking plus an output ceiling, and cached-token accounting. Wiki's endpoint guard and saved continuation are bound to Interactions. The transition should remove vendor transport code only if these gaps are solved without creating an equivalent replacement wrapper.

Scope is **Gemini chat** through `AgentProviderService`. [Gemini media generation, Files API handling, and token counting](./agents-media.md) have distinct transport and authorization requirements; a chat-client switch does not remove them. Wiki's shared ActionKernel, approvals, page-evidence checks, quotas, session ownership, and consent remain application responsibilities regardless of SDK. Other providers already use Ax with narrow provider-specific adaptation in [`factory.ts`](../server/agents/providers/factory.ts).

Media capability admission is currently tied to `gemini-api` profiles on the official base URL, with validation text that explicitly names Interactions ([registry](../server/agents/providers/registry.ts), [media guide](./agents-media.md)). Switching chat endpoints must not accidentally disable PDF/image attachments, image creation/editing, or transcription. Keeping their separate Google transports does not by itself preserve the profile gates or their shared billing and consent behavior.

## How the current transport became the default

Commit `eb5f91c0da0d08871059f879e3066c72d217ec9e` (2026-08-27, `refactor: use Gemini Interactions exclusively`) replaced an existing Ax-native Gemini `generateContent` integration with the local Interactions adapter. The commit establishes the protocol and continuation cutover; its message does **not** identify a failing Ax bug as the cause. Do not retroactively describe that migration as forced by a proven Ax defect. Google says Interactions had become generally available in June 2026, so its adoption was not premature by API-release status; whether a custom implementation was justified by Wiki's feature requirements is a separate question.

Today [`factory.ts`](../server/agents/providers/factory.ts) selects [`createGeminiInteractionsService`](../server/agents/providers/gemini-interactions.ts), allowlists the exact `/v1beta/interactions` endpoint, uses the `gemini-interactions-v1` continuation dialect, and restricts Gemini chat profiles to Gemini 3.x. The adapter implements Ax's `chat` interface itself and sends `store: false`; Wiki sends client-managed history instead of using `previous_interaction_id`. It requests no background execution or managed agents. Consequently, Interactions' server-managed-history and background-work advantages, including the associated stateful-cache benefit, are **not** benefits the current Wiki chat receives. Both APIs support implicit caching in stateless use; `generateContent` additionally supports explicit caching and custom safety settings that Interactions does not currently support ([Google's comparison](https://ai.google.dev/gemini-api/docs/interactions-overview#limitations), [caching](https://ai.google.dev/gemini-api/docs/generate-content/caching)).

## Feature and ownership comparison

| Wiki requirement | Interactions today | Google `generateContent` / installed Ax 24.0.24 |
| --- | --- | --- |
| Ordinary native Wiki functions and multi-turn reasoning | The adapter maps actions to `function_call` / `function_result` steps and replays IDs, arguments, and signatures. | Google supports function calls and requires replay of Gemini 3 signatures ([thought-signature guide](https://ai.google.dev/gemini-api/docs/generate-content/thought-signatures)); installed Ax captures and replays a native function-call signature. This is **not** a reason by itself to retain Interactions. |
| Built-in Google Search combined with Wiki actions | Ordered `google_search_call` / `google_search_result` steps and signatures are kept alongside Wiki function calls/results, even with `store: false`; the adapter extracts inline citation annotations and transient Search Suggestions. | Google exposes built-in `toolCall` / `toolResponse` parts for replay with `includeServerSideToolInvocations: true` and `VALIDATED` mode, and supplies inline grounding ranges and suggestion HTML in a different metadata shape ([tool combination](https://ai.google.dev/gemini-api/docs/generate-content/tool-combination), [Search metadata](https://ai.google.dev/gemini-api/docs/generate-content/google-search)). Installed Ax sends neither the circulation flag nor a complete mapping of those parts, grounding ranges, and suggestions. **This matters only while the Search feature remains in scope.** |
| Wiki action JSON schemas without Search | [`nativeFunctionParameters`](../server/agents/providers/gemini-interactions.ts) retains union branches and exposes common root properties. | Ax uses `parametersJsonSchema` but its [`cleanSchemaForGemini`](https://github.com/ax-llm/ax/blob/24.0.24/src/ax/ai/google-gemini/api.ts#L423-L470) drops `oneOf` and `anyOf`. The real `memory.manage` action has three `action`-discriminated variants ([catalog](../server/agents/actions/catalog.ts)). The action kernel would still enforce validity; the model would no longer see the full argument contract. Whether a corrected native schema is accepted by a live Gemini model needs verification. |
| Configured thinking with an output ceiling | The adapter sends `thinking_level` and `max_output_tokens` together. | Wiki always supplies `modelConfig.maxTokens` ([engine](../server/agents/providers/engine.ts)); installed Ax [throws before dispatch](https://github.com/ax-llm/ax/blob/24.0.24/src/ax/ai/google-gemini/api.ts#L1395-L1429) when its Gemini `thinkingLevel` is also set. Preserve the configured reasoning-effort and output-budget behavior, or make an explicit product tradeoff; neither should silently disappear. This local guard alone does not prove Google's endpoint cannot support another configuration. |
| Cached-token accounting | Interactions reports total input including cached input; the adapter passes that inclusive figure into Wiki's [`gemini-api` usage normalizer](../server/agents/providers/usage.ts). | Ax reports uncached prompt tokens and cached read tokens separately ([mapping](https://github.com/ax-llm/ax/blob/24.0.24/src/ax/ai/google-gemini/api.ts#L1792-L1808)). The current Gemini normalizer would undercount full input if the Ax result were substituted unchanged. Fix the mapping *before* quota or cost settlement. |
| Files API attachments and no-tools final answer | The adapter admits validated Gemini Files references and explicitly sets `tool_choice: "none"` when there are no declared tools. | Ax maps `fileUri` to Gemini `fileData` and can request function-calling mode `NONE`. These need conformance and guarded-input checks, but are not known exclusive Interactions features. |
| Stateless continuation and egress | The saved assistant state is an integrity-checked, origin-bound Interactions-step envelope; transport is DNS-pinned and `/interactions`-only ([deployment contract](./agents-deployment.md)). | Native Ax emits `:generateContent` / `:streamGenerateContent`. It cannot consume the saved Interactions steps or pass the current endpoint guard. These are **migration boundaries created by our current implementation**, not missing Google model capabilities. |

### Evidence level and observed probes

At revision `7e50ba2ec0e4`, deterministic calls through the **installed** Ax 24.0.24 and Wiki adapter with intercepted HTTP, no provider credentials, established:

- Ax sent `/models/gemini-3.8-flash:generateContent`; Wiki sent `/interactions` with `store: false`. Feeding an Interactions-shaped response to Ax produced no parsed results or usage. The current egress guard rejected an Ax-native request before a network call.
- A simple Ax function loop emitted `parametersJsonSchema`, parsed a function call with a thought signature, and replayed that signature with the function result. Ax also sent `x-goog-api-key` rather than a query-string key. Earlier general objections that Ax cannot use functions or preserve TypeScript thought signatures are false. Upstream [PR #690](https://github.com/ax-llm/ax/pull/690) fixed TypeScript tool-schema handling; its missing-signature fix applied to generated language ports, not an absent TypeScript feature.
- With Google Search and a custom function, Ax sent `google_search` but did not request tool-context circulation. Given a synthetic mixed response containing Search tool-call/result parts, their signatures, grounding metadata, and a function call, it returned the function call but omitted the Search parts, their signatures, grounding ranges, and suggestion HTML. The Wiki adapter separately replayed signed Search steps and a matching Wiki function result in a synthetic follow-up.
- With the **actual** `memory.manage` JSON Schema from Wiki's action catalog and Search disabled, Ax emitted `parametersJsonSchema` containing only `$schema`; Wiki's adapter retained all three `oneOf` branches and the root action fields. This is an Ax mapping observation, **not** a live test of Google's acceptance of a corrected native schema.
- For a synthetic `promptTokenCount: 10`, `cachedContentTokenCount: 4`, `candidatesTokenCount: 2` response, Ax reported prompt 6 and cache read 4. Passing that unchanged into Wiki's `gemini-api` usage reader produced input 6, cached input 4, and total 12. Full input for quota and pricing must remain 10; a silent substitution is unsafe.
- Ax's thinking-level/output-ceiling incompatibility is visible in its local pre-dispatch check; the Wiki adapter sends both fields. No live Google API request was made to establish behavioral parity, latency, cost, acceptance of union schemas, or provider-side output-limit rules.

These are targeted synthetic transport and parser observations, **not** live-provider conformance. Ax versions, model capabilities, and provider APIs may change. Avoid treating old results as proof that a future Ax release still has the same gaps.

## Decision, options, and revisit trigger

**Current decision:** keep Interactions and preserve existing Search availability and session consent until a separate product decision changes them. No profile, continuation dialect, guard, persisted message, credential, or deployment changes are authorized by this report. The substantial local chat adapter is real maintenance debt; continuing it is not evidence that `generateContent` lacks Wiki's other chat features. A future migration is worth reconsidering if new Google Web Search calls are retired **and** Ax can support the remaining Wiki chat contract without replacing the adapter with another large vendor-specific wrapper. Alternatively, an upstream Ax Interactions implementation with complete provider metadata could reduce local wire code while retaining the present protocol.

**If Search remains:** evaluate Ax's complete built-in-tool context and grounding metadata coverage, not merely whether it can send `google_search: {}`. If Search is retired: stop *new* Search only through an explicit product change; preserve already saved answers, citations, and their normal retention/deletion rules. Disabling Search must not silently revoke Wiki action permissions or rewrite old conversations.

### Minimum cutover acceptance gates

1. **Prove the candidate with the real contract.** Exercise both selected main and utility Gemini models: native page read and `memory.manage` add/replace/remove schemas, multiple calls with stable IDs and signature replay, no-tools synthesis after compaction, JSON output where declared, streamed text with genuine terminal status, cancellation, bounded output, Files API image/PDF input, unexpected calls, and malformed/incomplete provider responses. Run profile conformance and a focused live Wiki Agent action/answer flow in addition to deterministic failure fixtures. If Search remains, include mixed Search → Wiki action → final answer with usable citations, Search Suggestions, and authority separation.
   - Separately exercise configured attachment upload/read, image creation/editing, transcription, media token counting, and their provider-profile availability after the chat cutover; preserve their existing permissions, storage/expiry, and accounting.
2. **Preserve accounting and trust boundaries.** Normalize uncached plus cached input exactly once, retain authoritative totals and quota/cost settlement, and fail closed on missing or malformed usage. Adjust only the Gemini endpoint allowlist to the required `generateContent` path(s); retain HTTPS-origin restriction, DNS pinning, redirect denial, credential headers, payload/stream bounds, and cancellation. Do not widen egress to arbitrary model paths or hosts.
3. **Cut over persisted continuation deliberately.** Never decode `gemini-interactions-v1` bytes as generateContent history. Bind a new dialect/capability revision to the replacement protocol, omit incompatible old provider-native state and fall back to canonical chat history under the existing origin/integrity rules; preserve existing messages, citation records, ownership, approvals, configuration, and secrets. Re-conform affected Gemini profiles before enabling them. Do not claim hidden provider context survives the fallback. Check old-session continuation and active approval behavior explicitly.
4. **Show a net maintenance gain.** Identify upstream Ax capabilities or accepted changes that remove local request/response/streaming wire translation. Retain Wiki-only policy and safety boundaries in Wiki. Compare affected-service build, typechecks, changed-path tests, provider smoke, and behavior against the current Interactions baseline before deleting the adapter. If one of the above gates fails, keep the present transport; do not mask the gap with a no-op compatibility layer or silently downgrade actions, reasoning, or accounting.
